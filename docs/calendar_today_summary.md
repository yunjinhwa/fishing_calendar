# 캘린더 오늘의 출조 기록 요약

브랜치: `feature/calendar-today-summary` · 대상: [추가 요구사항](pre-release-additional-requirements.md)의 U-07.

캘린더 아래에는 브랜치 시작 시점의 카드 디자인을 유지한 `오늘의 요약` 이동 버튼을 표시한다. 파도 아이콘·제목과 설명 두 줄·오른쪽 화살표 및 기존 여백·모서리를 그대로 사용한다. 설명은 현재 기능에 맞게 `오늘의 출조 기록을 확인할 수 있습니다.`로 바꿨다. 출조 기록의 날짜·건수·장소·시간은 버튼으로 여는 상세 화면에서 확인한다.

## 화면 구성과 이동

1. 캘린더의 `오늘의 요약` 버튼을 누르면 같은 제목의 상세 화면이 열린다. 캘린더에는 건수·미리보기·빈 상태·작성 버튼을 펼치지 않는다.
2. 상세 화면에는 오늘 날짜와 출조 건수, 오늘과 겹치는 전체 기록 목록을 표시한다. 시작 시각 순으로 정렬하고, 같은 시작 시각은 기록 ID 순으로 정렬한다.
3. 목록에서 장소·실제 시작/종료 시간·기록 요약과 기존 동기화 상태를 확인한다. 기록을 누르면 기존 기록 상세 화면으로 이동한다.
4. 오늘 기록이 없으면 상세 화면 안에서 안내와 `기록 작성` 버튼을 표시한다. 버튼을 누른 현재 날짜·시각으로 작성을 시작한다.
5. 뒤로 돌아오면 캘린더에서 보고 있던 연·월을 유지한다. 다른 연도·월을 조회하던 중에도 요약은 기기의 오늘 날짜를 기준으로 연다.

상세는 기존 [날짜별 기록 목록](../lib/presentation/calendar/daily_record_list_page.dart)의 오늘 요약 모드를 사용한다. 일반 날짜 선택은 기존 날짜별 기록 화면을 유지한다.

이동은 활성 캘린더와 `canManageRecords` 권한을 다시 확인하며 중복 실행을 막는다. 기록 관리 권한이 없는 상태에서는 요약 이동과 기록 표시를 허용하지 않는다. 목록·작성·기록 상세 화면에서 돌아온 뒤 현재 계정·세션을 확인한다. 요약 목록만 열고 캘린더로 돌아오면 추가 동기화를 요청하지 않는다. 개별 기록 상세에서 목록으로 돌아올 때는 기존 동기화를 유지해 감시 이벤트 없이 발생한 원격 변경도 반영한다.

## 날짜와 갱신 기준

[기록 모델](../lib/data/models/fishing_record.dart)의 기존 날짜 겹침 조건을 사용한다.

```text
기록 시작 < 내일 00:00 && 기록 종료 > 오늘 00:00
```

전날 시작해 오늘 새벽에 끝나는 기록과 오늘 시작해 다음 날 끝나는 기록은 오늘 요약에 각각 1건으로 포함된다. 오늘 00시에 정확히 끝난 기록과 내일 00시에 시작하는 기록은 포함하지 않는다. 월·연도 경계에서도 같은 기준을 적용한다.

날짜를 넘기는 기록은 양쪽 날짜와 실제 시간을 표시하고, 연도도 넘기면 양쪽 연도를 포함한다. 기록 시간을 오늘 범위로 잘라 표시하지 않는다.

[캘린더](../lib/presentation/calendar/calendar_page.dart)와 오늘 요약 상세는 다음 로컬 자정까지의 일회성 타이머를 사용한다. 자정에 오늘 날짜·상세 목록·오늘 강조 표시를 갱신하고 다음 자정을 예약한다. 앱 복귀와 캘린더 탭 재활성화 시에도 날짜를 다시 확인한다. 백그라운드에서는 타이머를 취소하고, 비활성 캘린더 탭도 예약을 중지한다. 화면 해제 시 타이머와 리스너를 정리하며 사용자가 보고 있던 달력의 연·월은 바꾸지 않는다.

기록 추가·수정·삭제와 동기화 반영은 기존 저장소 리스너를 통해 상세 목록에도 반영한다. 요약용 저장소나 기록 사본을 별도로 유지하지 않는다.

## 조회와 캐시

현재 계정의 메모리 기록을 오늘 날짜로 걸러 사용한다. 오늘과 겹치는 기록은 기존 최근 31일 캐시의 보존 대상이므로 요약용 월·전체 이력 조회나 추가 보유 범위(lease)를 등록하지 않는다. 유료 회원이 과거 달을 조회할 때도 그 달의 기존 캐시 정책과 오늘 요약은 구분된다.

무료·오프라인 상태에서는 기기에 있는 기록을 사용한다. 서버에만 있는 미동기화 변경까지 이 화면의 열람만으로 확인했다고 보장하지 않는다. 날씨·물때·수온 API 호출, DB 스키마, Firestore 규칙·인덱스, 사진 보관 정책은 변경하지 않는다.

## 검증 범위

- [버튼 테스트](../test/calendar_today_summary_card_test.dart): 캘린더에서 단일 버튼만 표시, 이동 콜백·비활성 상태, 좁은 화면·큰 글자.
- [캘린더 요약 테스트](../test/calendar_today_summary_test.dart): 버튼에서 상세 진입, 오늘 전체 기록의 날짜 겹침·정렬, 다른 달 조회 유지, 기록 변경 반영, 상세의 빈 상태·현재 시각 작성, 자정·앱 복귀·탭 재활성화, 접근 권한·계정 경계와 작은 화면.
- [월 캐시 테스트](../test/calendar_month_cache_navigation_test.dart): 과거 월 조회 중에도 오늘 기록을 유지하고 요약용 서버 조회나 보유 범위를 추가하지 않는지 확인.
- 기존 월 이동·연속 기록 표시·캐시·기본 화면 테스트로 기존 동작을 확인한다.

신규 테스트는 버튼 4개, 요약 상세·캘린더 연계 9개, 월 캐시 1개로 총 14개다. 기존 원격 기록 갱신 테스트를 통해 개별 기록 상세에서 돌아올 때 감시 이벤트 없이 발생한 서버 삭제도 반영되는지 확인했다. 실제 기기 조작과 최종 빌드·배포는 실행하지 않았다.

이후 이동 버튼을 기존 카드 디자인으로 복원한 뒤 버튼·상세 연계 테스트 13개와 변경 위젯·테스트의 정적 분석을 다시 통과했다. 전체 테스트 수는 위 기능 변경 검증 기준이다.

## 실제 기기 확인

테스트 계정과 테스트 기록을 사용한다.

| 확인 항목 | 절차와 기대 결과 |
|---|---|
| 캘린더 공간 | 캘린더 아래에 `오늘의 요약` 버튼만 보여야 한다. 기록 수·미리보기·작성 버튼을 캘린더에 펼치지 않아야 한다. |
| 상세와 전체 목록 | 오늘의 기록을 여러 개 저장하고 버튼을 누른다. `오늘의 요약` 제목·날짜·건수가 맞고, 시작 시각 순으로 오늘의 전체 기록을 스크롤해 볼 수 있어야 한다. |
| 기록 상세·복귀 | 요약 목록에서 기록을 누르면 기존 기록 상세가 열려야 한다. 뒤로 돌아오면 요약 목록과 원래 달력의 연·월이 유지되어야 한다. |
| 빈 상태 | 오늘 기록이 없는 계정으로 버튼을 누른다. 상세 안에 안내와 `기록 작성` 버튼이 보이고 현재 날짜·시각으로 작성이 시작되어야 한다. 저장 후 상세 목록에 반영되어야 한다. |
| 자정을 넘긴 기록 | 전날 18시~오늘 03시, 오늘 18시~내일 03시 기록을 각각 만든다. 두 기록 모두 오늘에 1건씩 포함되고 실제 날짜·시간이 표시되어야 한다. 오늘 00시에 끝난 기록은 제외되어야 한다. |
| 월 이동 | 과거·미래의 다른 달을 선택한 뒤 요약을 연다. 요약은 계속 오늘 기준이며 닫으면 기존에 선택한 달을 유지해야 한다. |
| 수정·삭제·동기화 | 기록 상세에서 장소·시간을 수정하거나 기록을 오늘 밖으로 옮기고 삭제한다. 요약의 건수·목록이 갱신되어야 한다. 유료 계정은 동기화된 다른 기기의 변경도 반영되는지 확인한다. |
| 날짜 변경 | 자정 전후 요약 상세를 열어 두거나 날짜가 바뀐 뒤 앱·캘린더 탭으로 돌아온다. 상세 날짜·목록과 오늘 강조 표시가 갱신되고 보고 있던 달력의 연·월은 유지되어야 한다. |
| 계정·오프라인 | 로그아웃·다른 계정 로그인 시 이전 계정 기록이 남지 않아야 한다. 오프라인에서도 기기에 저장된 오늘 기록을 볼 수 있어야 한다. |
| 작은 화면·큰 글자 | 시스템 글자 크기를 키운다. 캘린더의 월 이동·날짜 탭·요약 버튼을 사용할 수 있고 상세의 전체 목록과 빈 상태 작성 버튼에 스크롤로 접근할 수 있어야 한다. |
