# 물때·수온 선택 입력

2026-11-09 사용자 결정에 따라 기록 작성·수정에서 물때와 수온을 바다·민물·내륙 구분 없이 선택 항목으로 제공한다.

## 입력 기준

- 두 항목을 모두 비우거나 한 항목만 입력해도 저장할 수 있다. 앞뒤 공백을 제거한 뒤 빈 값은 `null`로 저장한다. 미입력을 `0`, `해당 없음` 같은 임의의 값으로 채우지 않는다.
- 물때는 기존 100자 제한을 유지한다. 수온은 입력했을 때만 유한한 숫자로 검사하며 `0`, 음수, 소수를 허용한다. 문자·NaN·Infinity·숫자 범위를 벗어난 값은 저장하지 않는다.
- 위치·장르·유효한 시작/종료 시간·날씨·기온은 기존 입력 규칙을 유지한다. 조과는 계속 개체별로 입력하며 마릿수 필드를 추가하지 않는다.
- 기존 기록의 물때·수온을 수정 화면에서 비우면 미입력으로 갱신한다. 상세에서는 다른 미입력 항목과 같이 `-`로 표시한다.
- 기존 자동 입력의 위치·시간·수역 조건은 유지한다. 사용자가 직접 지운 값은 저장 시 자동으로 다시 채우지 않는다. 지도에서 민물·내륙에 해양 API 정보를 표시하지 않는 정책도 유지한다.

모델, SQLite 열, Outbox, Firestore 문서와 보안 규칙은 기존 nullable 필드를 사용한다. 새 DB 버전이나 데이터 이전, Firebase 설정·규칙 배포는 필요하지 않다. 기존 기록과 대기 중인 요청은 그대로 유지하고, 새로운 저장·수정 요청에 선택 입력을 적용한다. 기존 값을 지운 수정 요청은 null을 보내 서버의 이전 값도 비운다.

## 실제 기기 확인

1. 바다와 민물에서 각각 기록 작성을 열고 물때·수온을 비운다. 나머지 필수값을 채워 저장한 뒤 상세와 앱 재실행 후에도 미입력인지 확인한다.
2. 물때만 입력한 기록, 수온만 입력한 기록을 저장한다. 수온 `0`, `-1.5`, `18.2`는 입력한 수치대로 유지되어야 한다. 문자·NaN·Infinity는 입력 안내와 함께 저장이 차단되어야 한다.
3. 기존 물때·수온이 있는 기록을 수정해 두 값을 비우고 저장한다. 다시 수정 화면을 열어도 비어 있어야 한다. 자동으로 채워진 물때·관측 수온을 지운 뒤 저장해도 같은지 확인한다.
4. 날씨·기온이 없으면 기존대로 저장이 차단되는지 확인한다.
5. 유료 계정에서 오프라인으로 기존 두 값을 지우고 저장한 뒤 앱을 재실행한다. 연결 복구·동기화 후 다른 기기에서도 값이 비워져야 한다. 기존의 사진 로컬 보관과 계정 분리는 유지되어야 한다.
