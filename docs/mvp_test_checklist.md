# Fishing Build MVP 테스트 체크리스트

이 문서는 사용자가 앱에서 확인할 수동 점검 목록이다. 체크되지 않은 항목은 미확인이며, 자동 테스트 통과만으로 완료 표시하지 않는다. 현재 자동 검증 결과와 미해결 사항은 [MVP 통합 점검 보고서](mvp_integration_check.md)에 별도로 기록한다.

## 점검 기준과 현행 정책

- 조과 항목 하나는 물고기 한 마리다. 같은 어종 여러 마리는 조과 항목을 각각 추가하며 수량 필드를 요구하지 않는다.
- 출조 사진은 현재 기기의 로컬 파일이다. Firebase Storage를 사용하지 않으며, 다른 기기로 동기화되는 것은 사진을 제외한 기록 본문이다.
- 도감은 검증된 실제 어종 사진을 사용한다. 자료가 없는 종을 다른 종이나 삽화로 대체하지 않으며, 이번 점검에서 추가 자료 수집·보강은 진행하지 않는다.
- 지도·지도 상세의 물때·수온·만조·간조는 바다·해안에서만 제공한다. 민물·내륙·판별 불가 위치에서는 해양 API 요청과 해당 표시를 차단한다. 지도에 표시할 값이 없으면 `제공되지 않음`으로 안내하고 출처·격자·발표 기준은 노출하지 않는다.
- 기록 충돌은 기존의 내 변경 적용 / 상대 변경 적용 / 직접 병합으로 해결한다. 자동 최종 쓰기 우선 처리를 통과 조건으로 요구하지 않는다. 같은 Outbox 요청의 ID·본문·작업 종류·기준 버전은 유지하고 최신 변경은 후속 요청으로 보존한다.
- 비밀번호 재설정 기능을 통합한다. Firebase Console의 재설정 메일 작업 URL 맞춤설정은 사용자 확인으로 저장 완료되었다. 실제 메일 수신·링크에서 비밀번호 변경·새 비밀번호 로그인까지의 전체 흐름은 아직 미확인이며, 아래 수동 점검 항목을 완료한 것으로 간주하지 않는다.

물때와 수온은 수역 구분 없이 선택 입력이다. 바다·민물·내륙 모두 비워 두고 저장할 수 있으며, 입력한 수온은 유한한 숫자여야 한다. 날씨·기온은 필수로 유지한다. 자동 입력과 수동으로 지운 값의 처리 기준은 [물때·수온 선택 입력](optional_record_conditions.md)을 따른다.

## 1. 앱 실행 / 기본 이동

- [ ] 앱 실행 시 로그인 선택 화면이 표시된다.
- [ ] 비회원으로 시작하기를 누르면 메인 화면으로 이동한다.
- [ ] 하단 탭이 표시된다.
- [ ] 비회원은 지도와 도감을 이용할 수 있다.
- [ ] 비회원이 캘린더 / 기록 / 내정보 탭을 누르면 로그인 안내가 표시된다.

## 2. 인증 화면

- [ ] 로그인 버튼을 누르면 로그인 화면으로 이동한다.
- [ ] 회원가입 버튼을 누르면 회원가입 화면으로 이동한다.
- [ ] 로그인 필수값이 비어 있으면 안내 메시지가 표시된다.
- [ ] 로그인 이메일 형식이 올바르지 않으면 안내 메시지가 표시된다.
- [ ] 로그인 화면에서 비밀번호 재설정으로 이동하면 입력했던 이메일이 유지된다.
- [ ] 가입 이메일로 재설정 메일을 요청하고 링크에서 변경한 새 비밀번호로 로그인할 수 있다.
- [ ] 존재하지 않는 이메일에도 같은 확인 안내를 표시하고, 요청 중 중복 전송·전송 후 60초 이내 재전송을 막는다.
- [ ] 네트워크 오류·요청 제한은 재시도 안내를 표시하며 인증 서비스가 없는 실행 환경에서는 전송을 비활성화한다.
- [ ] 가입되지 않은 이메일 또는 잘못된 비밀번호로 로그인할 수 없다.
- [ ] 이전 버전에서 복원된 회원은 기존 로그인 상태에서 비밀번호를 설정하기 전에는 로그아웃할 수 없다.
- [ ] 비밀번호가 없는 이전 계정은 로그인 화면에 입력한 임의 비밀번호를 새 비밀번호로 저장하지 않는다.
- [ ] 회원가입 필수값이 비어 있으면 안내 메시지가 표시된다.
- [ ] 회원가입의 이용약관·개인정보 처리방침 내용 보기를 열고 뒤로 돌아와도 입력값과 동의 체크 상태가 유지된다. 문서를 읽는 것만으로 자동 동의되지 않는다.
- [ ] 네트워크를 끈 상태에서도 두 문서를 스크롤하여 읽을 수 있으며, 내정보의 약관 및 정책에서도 같은 본문을 열 수 있다. 현재 본문의 초안 표시와 미확정 운영 정보를 확인한다.
- [ ] 회원가입·메일 링크 재설정 비밀번호는 8자 이상이며 영문(대소문자 무관)과 숫자를 포함해야 한다. 특수문자는 선택이다.
- [ ] 회원가입 닉네임은 2~20자의 한글, 영문, 숫자, 공백, 밑줄, 하이픈만 허용한다.
- [ ] 서로 다른 이메일로 같은 닉네임을 가입하면 두 번째 가입이 거절된다.
- [ ] 닉네임 앞뒤 공백과 영문 대소문자를 바꿔도 중복으로 판정된다. (`Fisher` / ` fisher `)
- [ ] 중복 닉네임으로 실패한 신규 Firebase 계정은 남지 않아 같은 이메일로 다시 가입할 수 있다.
- [ ] 예약 정보가 없는 기존 Firebase 계정의 닉네임이 충돌하면 로그인 중 새 닉네임 입력창이 표시된다.
- [ ] 기존 계정에서 새 닉네임을 입력하면 기록을 잃지 않고 로그인이 완료된다.
- [ ] 두 기기에서 같은 닉네임을 동시에 제출해도 한 계정만 성공한다.
- [ ] 로그인 세션이 있는 기기는 네트워크를 끊고 앱을 다시 시작해도 저장된 닉네임으로 복원된다.
- [ ] 네트워크가 끊긴 상태의 새 로그인·회원가입은 닉네임 예약 없이 완료되지 않는다.
- [ ] 로그인 성공 후 메인 화면으로 이동한다.
- [ ] 회원가입 성공 후 메인 화면으로 이동한다.
- [ ] Firebase 연결 환경에서 앱 재실행 후 회원 세션이 복원된다.
- [ ] 기존 로컬 계정의 비밀번호가 일치할 때 기록과 Outbox가 Firebase UID 소유권으로 이전된다.
- [ ] 같은 이메일의 Firebase 계정이라도 로컬 비밀번호가 다르면 기존 기록과 플랜이 이전되지 않는다.
- [ ] 이미 가입된 이메일로 회원가입하면 중복 안내가 표시되고 기존 플랜이 유지된다.
- [ ] 회원가입 후 무료 회원 상태가 적용된다.
- [ ] 로그인 상태 유지 해제 후 앱을 다시 시작하면 로그인 선택 화면이 표시된다.
- [ ] Firebase 모드의 플랜 정보에서 서버 플랜 새로고침으로 계정의 무료/유료 권한을 확인한다. 앱에 직접 전환 버튼이 표시되지 않는다.
- [ ] 로컬 개발 모드에서만 무료/유료 전환을 사용할 수 있고, 변경한 개발용 플랜이 앱 재시작과 다음 로그인 후에도 유지된다.
- [ ] Firebase 모드에서 오프라인이면 마지막으로 검증한 계정별 플랜 캐시가 적용되고, 검증된 캐시가 없으면 무료 권한이 적용된다.
- [ ] 로그아웃 후 다른 계정으로 로그인하면 이전 계정의 기록과 Outbox가 표시되지 않는다.
- [ ] 계정 소유자가 없는 이전 버전 기록은 자동 귀속되지 않고 이전 기기 기록 보관함에 남는다.
- [ ] 이전 기기 기록은 소유권 경고를 확인하고 가져오기를 선택한 뒤에만 현재 계정에 추가된다.
- [ ] 기존 기록이 있는 무료 회원의 유료 전환 시 기록이 업로드 대기열에 등록된다.
- [ ] 기존 기록 이전이 끝나기 전에는 클라우드 동기화가 제한된다.
- [ ] 로컬 개발 모드에서는 대기 또는 실패한 업로드가 있으면 무료 플랜 전환이 제한된다. Firebase 서버에서 무료로 변경되면 클라우드 접근은 차단되고 미전송 Outbox는 보존된다.
- [ ] 무료 회원에게 동기화 기능 대신 유료 플랜 안내가 표시된다.
- [ ] 유료 회원은 동기화 / 충돌 관리 화면으로 이동할 수 있다.

## 3. 출조 기록 작성

- [ ] 기록 탭에서 출조 기록 작성 화면으로 이동한다.
- [ ] 위치를 입력하지 않으면 안내 메시지가 표시된다.
- [ ] 낚시 장르를 선택하지 않으면 안내 메시지가 표시된다.
- [ ] 종료 시간이 시작 시간보다 빠르거나 같으면 안내 메시지가 표시된다.
- [ ] 날씨·기온을 입력하지 않으면 안내 메시지가 표시된다.
- [ ] 바다·민물·내륙 모두 물때·수온을 비워 두거나 각각 하나만 입력해 저장할 수 있다. 수정 화면에서 기존 값을 지운 뒤 저장·재실행해도 미입력이 유지된다.
- [ ] 수온 `0`과 음수·소수는 입력값대로 보존되고 문자·NaN·Infinity 등 잘못된 값은 저장되지 않는다.
- [ ] 기온/수온에 숫자가 아닌 값을 입력하면 안내 메시지가 표시된다.
- [ ] 조과 추가 버튼을 누르면 조과 입력 카드가 추가된다.
- [ ] 조과 카드 하나에 한 마리의 어종·크기·무게를 입력하며 수량 입력란이 없다. 같은 어종 두 마리를 서로 다른 조과 카드로 저장하고 다시 열면 각각 유지된다.
- [ ] 조과 삭제 버튼을 누르면 조과 입력 카드가 삭제된다.
- [ ] 조과가 1개만 남았을 때 삭제하면 안내 메시지가 표시된다.
- [ ] 어종 없이 크기 또는 무게만 입력하면 안내 메시지가 표시된다.
- [ ] 사진을 첨부해 저장한 뒤 앱을 다시 실행하면 같은 기기의 기록 상세에서 사진이 유지된다.
- [ ] 정상 입력 후 저장하면 기록 탭 화면으로 돌아간다.

## 4. 캘린더 / 날짜별 기록

- [ ] 저장한 기록이 캘린더 날짜 칸에 표시된다.
- [ ] 날짜를 선택하면 날짜별 기록 목록 화면으로 이동한다.
- [ ] 기록이 있는 날짜에는 기록 목록이 표시된다.
- [ ] 기록이 없는 날짜에는 빈 상태 화면이 표시된다.
- [ ] 날짜별 기록 목록에서 기록을 누르면 상세 화면으로 이동한다.
- [ ] 상세 화면에서 기록을 삭제할 수 있다.
- [ ] 삭제 후 날짜별 기록 목록에서 기록이 사라진다.
- [ ] 날짜별 기록 목록에서 뒤로가기 시 캘린더가 갱신된다.

## 5. 기록 검색 / 필터

- [ ] 기록 탭에서 기록 검색 화면으로 이동한다.
- [ ] 장소 검색이 동작한다.
- [ ] 어종 검색이 동작한다.
- [ ] 메모 검색이 동작한다.
- [ ] 낚시 장르 필터가 동작한다.
- [ ] 시작일/종료일 기간 필터가 동작한다.
- [ ] 시작일/종료일 개별 초기화가 동작한다.
- [ ] 최신순/오래된순 정렬이 동작한다.
- [ ] 검색 결과 개수가 표시된다.
- [ ] 검색 결과가 없으면 빈 상태 화면이 표시된다.
- [ ] 검색 결과를 누르면 기록 상세 화면으로 이동한다.

## 6. 지도 / 날씨 API

- [ ] 지도 탭으로 이동한다.
- [ ] 위치 검색 시 선택 위치가 변경된다.
- [ ] 외부 데이터 조회 로딩 상태가 표시된다.
- [ ] 조회 성공 시 날씨·기온이 표시되고 지도 결과 카드에 출처·격자·발표 기준이 노출되지 않는다.
- [ ] 오프라인·좌표 없는 장소·미설정 인증키에 조회 불가 안내가 표시된다.
- [ ] 실패해도 장소명·좌표를 전달하고 날씨 항목은 직접 입력할 수 있다.
- [ ] 정상 상태에서 같은 시간대·위치의 날씨·기온이 자동 입력된다. 물때·관측 수온은 각각의 날짜·장소·시각 조건으로 별도 처리한다.
- [ ] 시작 시간대나 위치 변경 시 자동 입력값만 지워지고 직접 고친 값은 유지된다.
- [ ] 바다·해안의 조석 예보에서 가까운 지점·날짜를 선택하고 만조·간조 시각·cm 단위 조위를 확인한다.
- [ ] 바다·해안에서는 날씨 조회가 실패해도 조석 예보가 별도로 조회된다.
- [ ] 기록의 날짜·장소와 일치할 때만 만조·간조 참고 정보가 표시된다. 물때 명칭과 관측 수온은 각 적용 조건에 따라 자동 입력되며 직접 수정하거나 비운 값은 보존된다.
- [ ] 현재 관측 수온은 과거·미래 기록에 자동 입력되지 않고, 수온 조회 실패가 날씨·조석 조회를 막지 않는다. 수온만 재시도할 수 있다.
- [ ] 과거 정보에서 날짜·KST 시간을 선택하면 해당 시점의 관측 날씨·기온과 바다·해안의 수온을 조회하고, 같은 과거 시각의 기록 작성으로 연결한다. 현재 예보·수온으로 과거 자료를 대체하지 않는다.
- [ ] 지도에서 바다·민물·내륙을 자동 판별한다. 흰여울문화마을 같은 바다 경계 500m 이내 해안 육지에서는 바다 정보를 표시하고, 민물·내륙·판별 불가 위치에서는 물때·수온·만조·간조를 표시하거나 조회하지 않는다.
- [ ] 바다 정보를 불러오는 중 민물·내륙으로 바꾸어도 늦게 도착한 응답이 이전 해양 정보를 다시 표시하지 않는다. 지도 상세와 과거 정보 조회에서도 해양 정보 범위가 유지된다.
- [ ] 통합 카드의 날짜·지점 변경에 맞춰 물때가 바뀌고, 없는 값은 `제공되지 않음`으로 표시된다. 출처·격자·발표 기준 등 불필요한 정보가 노출되지 않는다.
- [ ] 위치 대체 입력 화면으로 이동할 수 있다.
- [ ] 추천 장소 선택 시 지도 화면의 위치가 변경된다.
- [ ] 지도 상세 화면으로 이동할 수 있다.
- [ ] 과거 정보 조회 화면으로 이동할 수 있다.

## 7. 어류도감

- [ ] 도감 탭으로 이동한다.
- [ ] 어류도감 목록이 표시된다.
- [ ] 어종 검색이 동작한다.
- [ ] 전체 / 바다 / 민물 / 금어기 필터가 동작한다.
- [ ] 검색 결과가 없으면 빈 상태 화면이 표시된다.
- [ ] 어종을 누르면 상세 화면으로 이동한다.
- [ ] 상세 화면에 기본 정보와 금어기 정보가 표시된다.
- [ ] 목록과 상세의 사진이 해당 어종의 실제 사진이며, 사진 미제공·로딩 실패·오프라인에서는 안내 또는 기본 아이콘을 표시한다. 모든 어종에 사진이 있다고 가정하지 않는다.
- [ ] 이 어종으로 기록 작성하기를 누르면 기록 작성 화면으로 이동한다.
- [ ] 선택한 어종이 조과 1에 자동 입력된다.

## 8. 개인 기록어

- [ ] 내정보에서 내 기록어 화면으로 이동한다.
- [ ] 기록어가 없으면 빈 상태 화면이 표시된다.
- [ ] 어종과 크기 또는 무게가 있는 기록을 저장하면 기록어가 표시된다.
- [ ] 크기순 정렬이 동작한다.
- [ ] 무게순 정렬이 동작한다.
- [ ] 이름순 정렬과 어종명 검색·검색어 지우기가 동작한다. 검색 결과가 없으면 빈 결과 안내가 표시된다.
- [ ] 기록어 항목을 누르면 상세 화면으로 이동한다.
- [ ] 공유 이미지 미리보기에서 선택한 크기/무게 기록 한 건의 수치와 출조 사진이 표시된다.
- [ ] 닉네임·사진·크기·무게 포함 여부를 바꿀 수 있고, 날짜·장소는 기본적으로 제외된다.
- [ ] 이미지 저장 후 갤러리의 PNG가 미리보기와 일치하고, 공유하기로 기기 공유 화면이 열린다.
- [ ] 사진이 없어도 대체 표시로 저장할 수 있으며, 닫기·공유 취소·권한 거부 후 재시도가 정상 동작한다.
- [ ] 다른 기기에서 같은 기록을 내려받으면 기록어 수치·날짜·장소는 유지되고, 로컬 사진이 없는 기기에서는 사진이 대체 표시된다.
- [ ] 미리보기 도중 원본 기록 변경·삭제·로그아웃 시 이전 이미지를 새로 저장하거나 공유하지 못한다.

## 9. 오프라인 / Outbox / 충돌

- [ ] 네트워크를 끊으면 오프라인 화면의 상태 안내가 자동으로 갱신된다.
- [ ] 네트워크를 다시 연결하면 화면 이동 없이 연결 상태 안내가 갱신된다.
- [ ] 다시 시도 버튼을 누르면 현재 연결 상태를 즉시 다시 확인한다.
- [ ] 네트워크를 바꾼 뒤 앱을 백그라운드에서 복귀시키면 현재 상태를 다시 확인한다.
- [ ] 비회원의 오프라인 진입 시 로그인 안내 화면이 표시된다.
- [ ] 무료 회원의 오프라인 안내에서 로컬 기록 작성 / 조회 정책이 표시된다.
- [ ] 유료 회원의 오프라인 안내에서 캐시 / Outbox 정책이 표시된다.
- [ ] 내정보에는 현재 플랜에 맞는 오프라인 진입 항목만 표시된다.
- [ ] 무료 회원은 Outbox와 동기화 / 충돌 내용을 열 수 없다.
- [ ] 유료 회원 화면에서 대기열 보기로 이동한다.
- [ ] outbox 대기/성공/실패/충돌 상태가 표시된다.
- [ ] 유료 회원의 기록 생성 / 수정 / 삭제 요청이 같은 기록 ID로 outbox에 저장된다.
- [ ] Outbox에는 요청 당시 기록 payload와 계정 식별자가 저장된다.
- [ ] 앱을 다시 실행해도 미전송 Outbox 항목이 유지된다.
- [ ] Outbox 저장 직후 앱이 종료되어도 재실행 시 기록이 복구된다. 마이그레이션 대기나 무료 기간의 후속 변경이 있으면 오래된 요청 본문이 최신 로컬 변경을 덮어쓰지 않는다.
- [ ] 중단된 플랜 전환을 다시 실행해도 기존 Outbox 요청의 ID·본문·작업 종류·기준 버전은 바뀌지 않는다. 무료 기간의 최신 수정·삭제는 새 ID의 후속 요청으로 반영된다.
- [ ] 서버 반영 후 응답이 유실된 요청을 재시도해도 같은 요청의 영수증으로 복구되어 기록이나 변경이 중복 반영되지 않는다.
- [ ] 빈 Outbox 화면을 열어도 테스트용 항목이 자동 생성되지 않는다.
- [ ] 실패 항목 재시도 버튼이 동작한다.
- [ ] 전체 전송 처리 버튼이 동작한다.
- [ ] 완료 항목 정리 버튼이 동작한다.
- [ ] 기록 이전 중에는 완료된 이전 항목을 정리해도 이전 완료 판정이 고착되지 않는다.
- [ ] 내정보에서 동기화/충돌 관리 화면으로 이동한다.
- [ ] 충돌 목록이 표시된다.
- [ ] 충돌 상세 화면으로 이동한다.
- [ ] 내 변경 적용 / 상대 변경 적용 / 직접 병합 처리가 동작한다.
- [ ] 충돌 해결 후 미해결 충돌 수가 갱신된다.
- [ ] 같은 기록을 두 기기에서 수정하면 먼저 동기화한 값은 유지되고 다른 기기에는 충돌이 표시된다.
- [ ] 앱을 다시 실행해도 미해결 충돌과 양쪽 변경 내용이 유지된다.
- [ ] 상대 변경을 적용하면 서버 최신 값을 다시 조회하며 현재 기기의 사진이 유지된다.
- [ ] 내 변경 또는 직접 병합을 적용하는 동안 서버가 다시 바뀌면 새 충돌이 표시된다.
- [ ] 로컬 수정/서버 삭제와 로컬 삭제/서버 수정 충돌이 각각 올바르게 해결된다.

## 10. 최종 점검

자동 검증의 명령·결과·적용 범위는 [MVP 통합 점검 보고서](mvp_integration_check.md)에서 확인한다. 아래 화면·기기 확인은 자동 검증과 별도로 진행한다.

- [ ] 내정보 → 앱 정보에서 설치한 앱의 버전·빌드 번호와 API·데이터·이미지 출처를 확인한다. [세부 확인 절차](app_info_and_licenses.md)
- [ ] 출처 상세에는 제공기관·제작자와 라이선스만 표시되고, 사용 내용·이용조건·안내와 어종별 출처 메뉴는 표시되지 않는다. 개별 저작권 정보는 오픈소스 라이선스의 `어류 자료 저작권 고지`에서 확인한다. 출처 열람은 새 도감 API·이미지 요청을 만들지 않아야 한다.
- [ ] 오프라인에서도 출처·오픈소스 라이선스 전문을 읽을 수 있고, 온라인에서는 공식 출처와 개별 이용조건 링크가 외부 브라우저로 열린다.
- [ ] 앱 실행 중 빨간 overflow 메시지가 표시되지 않는다.
- [ ] 주요 화면에서 뒤로가기 동작이 자연스럽다.
- [ ] 사용자에게 보이는 문구에 불필요한 개발 브랜치명이나 내부 구현명이 노출되지 않는다.
- [ ] GitHub PR에 작업 범위와 확인 내용이 정리되어 있다.

## 11. 사용자 통합 실행 시나리오

테스트용 계정과 기록으로 실행하고, 실패 시 화면·기기·계정·재현 순서를 통합 점검 보고서에 남긴다. Firebase 플랜 변경 준비는 [서버 플랜 설정](server_plan_entitlement.md), 세부 전환 절차는 [기록 보존](plan_migration_integrity.md)을 따른다.

- [ ] 비회원으로 지도·도감을 둘러보고 보호된 탭의 로그인 안내를 확인한 뒤, 가입·로그인·앱 재실행으로 같은 계정이 복원되는지 확인한다.
- [ ] 바다·해안 지도에서 기록 작성으로 이동해 같은 어종 두 마리를 서로 다른 크기·무게와 함께 입력하고 사진을 저장한다. 재실행 후 캘린더·검색·상세·개인 기록어의 수치와 조과 연결이 일치하는지 확인한다.
- [ ] 바다 → 민물 → 내륙으로 위치를 바꾸며 해양 항목 숨김과 자료 없는 값의 `제공되지 않음` 표시를 확인한다. 각 위치에서 기록 작성으로 이동하고 물때·수온을 비워 저장한다. 자동 입력값을 직접 지운 경우에도 빈 값으로 저장되어야 한다.
- [ ] 유료 계정에서 오프라인 생성·수정·앱 종료·재실행 후 연결을 복구한다. 중복 없이 최신 기록이 동기화되고, 같은 기기 사진은 유지되며 다른 기기에는 기록 본문만 표시되는지 확인한다.
- [ ] 두 기기에서 같은 기록을 각각 수정하고 한쪽부터 동기화한다. 다른 쪽의 충돌을 재실행 후에도 확인하고 내 변경 / 상대 변경 / 직접 병합 선택 결과를 확인한다.
- [ ] 유료 → 무료 동안 기록을 수정·삭제하고 재실행한 뒤 다시 유료로 전환한다. 기존 요청이 유지되고 최신 수정·삭제가 후속 요청으로 반영되는지 확인한다.
- [ ] A 계정에서 대기 요청을 만든 뒤 B 계정으로 바꾸어 기록·사진·Outbox가 섞이지 않는지 확인한다. 다시 A로 로그인해 본인 기록의 처리를 재개한다.
- [ ] A 계정의 동기화 완료 후 B 계정으로 바꾸고 오프라인 또는 무료 상태로 동기화를 확인한다. B에게 A의 마지막 동기화 시각이 표시되지 않아야 하며, 같은 계정의 오프라인 재시도는 본인의 이전 성공 시각을 유지한다.
- [ ] 두 기기에서 같은 테스트 계정에 로그인하고 한쪽에서 탈퇴한다. 다른 기기에는 탈퇴 안내와 로그아웃만 표시되고, 해당 계정의 기록·Outbox·사진이 정리되며 다른 계정 데이터는 유지되어야 한다. 오프라인 기기는 연결 복구 후 확인한다.
- [ ] 개인 기록어에서 이름순·크기순·무게순과 어종 검색을 확인하고, 크기/무게의 근거 기록을 바꾸어 공유 이미지를 저장한다. 실제 갤러리·공유 화면, 사진 없는 기기의 대체 표시와 취소·권한 거부 후 재시도를 확인한다.
