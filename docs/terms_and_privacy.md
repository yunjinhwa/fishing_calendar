# 약관·개인정보 처리방침 열람

`feature/terms-and-privacy`에서 회원가입의 필수 동의 항목 옆에 **내용 보기**를 추가했다. 내정보의 **약관 및 정책**에서도 같은 문서를 열 수 있다. 사용자는 확정된 본문·운영 정보가 없어 검토용 초안으로 진행하는 것을 선택했다.

## 동작

- `PolicyDocumentPage`는 허용된 두 문서 중 하나를 앱에 포함한 UTF-8 텍스트 자산에서 읽는다. 웹뷰·외부 브라우저·새 의존성·네트워크 요청을 추가하지 않는다.
- 본문은 스크롤과 선택·복사가 가능하다. 로딩 실패나 빈 문서는 안내와 재시도를 제공한다. 문서·자산 번들이 바뀌면 다시 읽고 이전 문서의 늦은 결과를 표시하지 않는다.
- **내용 보기**와 동의 체크박스는 별도 조작이다. 읽기 완료로 자동 동의하지 않으며, 뒤로 돌아오면 이메일·닉네임·비밀번호 입력과 체크 상태가 유지된다.
- 회원가입 요청 중에는 내용 보기 버튼을 비활성화한다. 문서 열람은 인증·플랜·DB·Firestore 데이터를 변경하지 않는다.
- 원격 탈퇴 상태의 내정보는 기존 요구대로 탈퇴 안내·로그아웃 전용 화면을 유지한다.

## 본문 관리와 초안의 범위

본문은 `assets/legal/terms.txt`, `assets/legal/privacy.txt`이며 `pubspec.yaml`에 포함했다. 두 파일 모두 **검토용 초안 · 정식 시행 전**, 문서 버전 `draft-2026-11-09`와 작성 기준일을 표시한다. 운영자명·문의처·시행일은 미정으로 표시하며 현재 날짜를 시행일로 사용하지 않는다.

본문의 앱 처리 설명은 다음 실제 구현에 근거한다.

| 설명 | 확인한 구현 |
|---|---|
| Firebase 이메일 인증·닉네임·UID·플랜 | `firebase_auth_gateway.dart`, `auth_session_repository.dart` |
| 무료 기록 로컬 원본·유료 기록 본문 동기화 | `user_plan_policy.dart`, `firestore_record_sync_gateway.dart` |
| 좌표·기록·조과·선택 물때/수온 | `fishing_record.dart`, `record_form_page.dart` |
| 사진 로컬 보관·31일 기기 본문 캐시의 예외 | `record_photo_file_store_io.dart`, `record_cache_policy.dart`, `paid_cache_policy.md` |
| 위치 권한·카카오 검색/좌표·기상 격자·해양 관측소 | 지도 게이트웨이, 기상·조석·수온 서비스 |
| 도감의 어종·이미지 요청과 공유 이미지 전달 | 어류 제공자와 `share_image_exporter_io.dart` |
| 탈퇴의 순차 정리·다른 기기 처리·남는 UID 표식 | `account_deletion.md`, `firebase_auth_gateway.dart`, `account_deletion_service.dart` |

국외 처리와 공급자 보조 사본을 국내 보관·즉시 삭제로 단정하지 않았다. Firebase의 공식 안내는 Authentication의 미국 처리와 계정 삭제 이후 보조 사본 정리 기간을 설명한다. Firestore 등은 서비스와 프로젝트 설정에 따라 처리 위치가 달라질 수 있으므로 실제 운영 설정·계약을 확인할 항목으로 남겼다. [Firebase 개인정보·보안 안내](https://firebase.google.com/support/privacy)

초안의 구성은 처리 흐름을 적정하고 투명하게 공개하도록 안내하는 [개인정보보호위원회 2026 작성지침](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS217&mCode=D010030000&nttId=12018)을 참고했다. 법적 적합성이나 정식 운영 조건의 확정을 의미하지 않는다.

이번 범위는 문서 열람이다. 기존 동의 체크 조건을 유지하며, 서버에 동의 문서 버전·시각·증빙을 새로 저장하거나 새로운 개인정보 수집을 추가하지 않았다. 정식 본문을 확정할 때 수집·이용 동의와 처리방침 공개를 어떻게 구분하고 동의 이력을 관리할지도 함께 정해야 한다.

정식 운영 전 확정할 내용:

- 운영자와 개인정보 보호 담당자, 문의처, 시행일과 대상 이용자 범위.
- 실제 제공업체·계약 상대·처리 업무·저장 지역, 위탁·제공·국외 이전의 적용 사항.
- 삭제 표식·동기화 이력·로그·백업과 임시 공유 파일의 보유·정리 기준.
- 문의·권리행사 절차, 서비스 변경 안내, 실제 유료 상품을 운영할 경우 결제·해지·환불 조건.

이 기능은 외부 공개 정책 URL을 배포하지 않는다. 앱 배포 과정에서 외부 URL이 필요하면 확정된 본문과 운영 정보를 기준으로 별도 준비한다.

## 실제 기기 확인

새 텍스트 자산을 추가했으므로 기존 앱을 완전히 다시 실행한다. Firebase를 사용하는 경우 기존 실행 옵션과 로컬 API 설정을 유지한다.

1. 회원가입에 이메일·닉네임·비밀번호를 입력한다. 동의하지 않은 상태로 두 문서의 내용 보기를 각각 열고 스크롤한 뒤 돌아온다. 입력이 유지되고 자동 체크되지 않아야 한다.
2. 한 항목에 동의하고 문서를 다시 읽는다. 기존 체크 상태를 유지해야 하며, 나머지 동의 없이 가입을 제출하면 기존 필수 동의 안내가 나와야 한다.
3. 내정보에서 두 문서를 열어 회원가입과 같은 본문인지 확인한다. 문서를 열고 닫아도 로그인·요금제·기록 상태가 바뀌지 않아야 한다.
4. 비행기 모드에서도 문서가 표시되는지 확인한다. 작은 화면과 큰 시스템 글씨에서 본문과 내용 보기 버튼을 사용할 수 있어야 한다.
5. 두 문서의 검토용 초안 표시와 미정인 운영 정보를 확인한다. 본문 수정 후 앱을 다시 빌드·실행하면 동일 파일을 사용하는 두 진입점에 반영된다.

2026-11-09 자동 검증: 전체 Flutter 테스트 **1,247개 통과**, Dart 코드 분석 **`No issues found!`**. 문서의 실제 자산 로드·캐시·재시도·문서 교체, 회원가입 상태 보존, 작은 화면·큰 글씨, 회원 상태별 내정보 진입을 신규 테스트 11개로 확인했다. 관련 문서·탈퇴 화면 테스트 15개도 통과했다. 내정보 항목 추가로 달라진 위치에 맞춰 기존 탈퇴 테스트의 스크롤만 보완했으며, 탈퇴·동의 조건과 서버 데이터 구조는 바꾸지 않았다.
