# 이메일 비밀번호 재설정

로그인 화면의 **비밀번호를 잊으셨나요?** → 이메일 입력 → **재설정 메일 보내기**로 진행한다. 로그인 화면에서 입력한 이메일을 가져오며, **로그인으로 돌아가기**를 누르면 수정한 이메일을 로그인 화면에 반영하고 기존 비밀번호 입력은 비운다. 기존 로그인 유도 화면으로 돌아가는 흐름도 유지한다.

## 동작

- 기존 이메일 검증 규칙을 사용한다. 빈 값·잘못된 형식은 전송하지 않고 필드 아래에 안내한다. 이메일의 앞뒤 공백과 대소문자는 기존 계정 정규화 규칙을 따른다.
- Firebase Authentication의 `sendPasswordResetEmail`을 호출한다. 메일 언어는 한국어로 요청한다. 비밀번호 입력과 확인은 전용 재설정 웹 화면에서 처리하고, 링크 유효성 확인·실제 비밀번호 변경은 Firebase Authentication API를 사용한다.
- 전송 중 버튼·입력란을 비활성화하고 키보드 완료·연속 버튼 호출도 한 요청으로 처리한다. 정상 응답 후 현재 화면에서 60초 동안 재전송을 제한한다. 이메일을 바꿔도 이 대기 시간은 유지한다. 상단 **재설정 화면 새로고침**을 누르면 현재 입력한 이메일은 유지하고 안내·오류·대기 시간을 초기화해 다시 요청할 수 있다. 새로고침 자체는 메일을 보내지 않으며 전송 중에는 비활성화한다. 실제 서버 요청 제한은 Firebase 정책을 따른다.
- 계정 존재 여부를 드러내지 않도록 정상 응답·계정 없음·사용 중지 응답에 같은 확인 안내를 표시한다. 실제 수신 여부를 앱에서 단정하지 않는다. 네트워크 오류·과도한 요청·서비스 장애는 별도로 안내한다.
- 이메일 요청만으로 앱 로그인 상태, 계정 소유권, 요금제, 기록, 비밀번호 캐시를 바꾸지 않는다. 비밀번호는 사용자가 메일 링크에서 변경한다.
- 화면을 닫으면 타이머와 입력 컨트롤러를 정리하고 늦게 완료된 요청이 닫힌 화면을 갱신하지 않게 한다. 이미 요청한 메일은 화면을 닫아도 도착할 수 있다.

## 실행 설정

기존 Firebase 인증 설정을 사용한다. 기존 설정으로 Firebase 로그인이 가능한 상태에서 실행한다.

```powershell
& "C:\flutter\bin\flutter.bat" run --dart-define=FIREBASE_AUTH_ENABLED=true
```

지도·날씨 등의 로컬 설정 파일을 함께 사용하는 경우 기존 실행 명령에 포함된 옵션도 유지한다. Firebase가 꺼진 로컬 개발 인증 환경이나 인증 초기화 실패 상태에서는 전송 버튼을 비활성화하고 해당 실행 환경에서 메일을 보낼 수 없다고 안내한다.

Firebase Console의 Authentication 이메일 템플릿에서 비밀번호 재설정 메일의 발신 정보·표시 이름·링크 설정을 확인할 수 있다. [Firebase Flutter 사용자 관리 문서](https://firebase.google.com/docs/auth/flutter/manage-users#send_a_password_reset_email)를 참고한다. Auth Emulator를 사용하면 실제 편지함 대신 에뮬레이터에 표시되는 재설정 링크로 확인한다.

## 가입·재설정 공통 비밀번호 정책

2026-11-09 최종 사용자 요청은 **대소문자에 관계없이 영문+숫자, 8자 이상**이다. 앱의 가입·비밀번호 설정과 전용 재설정 화면에서 같은 규칙으로 검사한다.

- 최소 8자이며 영문 `A-Z` 또는 `a-z`와 숫자 `0-9`를 각각 한 글자 이상 포함한다.
- 대문자와 소문자를 모두 넣을 필요는 없다. 특수문자는 선택 사항이며 포함해도 된다. Firebase의 최대 길이는 기존 기본값인 4,096자를 유지한다.
- `password1`, `Password1`, `PASSWORD1`, `pass123!`은 허용한다. `password`, `12345678`, `pass12`는 거부한다.
- Firebase 서버 정책은 `ENFORCE`, `containsNumericCharacter: true`, `minPasswordLength: 8`이다. 대문자·소문자·특수문자 필수 옵션과 `forceUpgradeOnSignin`은 끈다. 기존 계정의 로그인에는 새 비밀번호 복잡도 검사를 추가하지 않는다.

Firebase 기본 정책은 대문자·소문자를 각각 필수로 지정하며, ‘둘 중 하나’나 정규식 조건을 제공하지 않는다. 따라서 서버의 최소 길이·숫자 검증 위에 앱과 전용 웹 화면의 영문 검증을 적용한다. 전용 화면은 영문만·숫자만 비밀번호를 전송하지 않는다. 화면 검증 자체를 Firebase 서버의 영문 필수 기능으로 해석하면 안 된다. 직접 REST API를 호출하면 서버 기본 조건만 적용되는 한계가 있다. [공식 비밀번호 정책 안내](https://firebase.google.com/docs/auth/web/password-auth#recommended_set_a_password_policy), [정책 API 필드](https://docs.cloud.google.com/identity-platform/docs/reference/rest/v2/projects.tenants#PasswordPolicyConfig), [커스텀 메일 처리 화면](https://firebase.google.com/docs/auth/custom-email-handler)을 참고한다.

## 재설정 웹 화면 배포

소스는 `auth_web/`, Hosting 설정은 `firebase.auth.json`이다. 전용 사이트 `fishingbuild-password-reset`을 사용한다. `node tool/prepare_password_reset_web.mjs`가 사이트의 공개 Firebase 초기화 설정을 읽어 `.dart_tool/auth_web_public`에 배포 파일을 준비한다. 최초 준비에는 관리 API의 `client.apiKey`와 프로젝트 ID만 담은 공개 설정 파일을 `--firebase-config=경로`로 지정할 수 있다. 액세스 토큰·서비스 계정 키는 배포 파일에 넣지 않는다.

```powershell
node tool/prepare_password_reset_web.mjs
& "$env:APPDATA\npm\firebase.cmd" deploy --config firebase.auth.json --only hosting --project fishingbuild
```

메일 템플릿의 action URL은 전용 사이트 루트로 연결한다. Firebase의 action URL은 모든 인증 메일에 공통 적용되므로, 비밀번호 재설정 외의 알려진 이메일 인증 작업은 기존 Firebase 화면의 고정 주소로 이어지는 버튼을 제공한다. 외부 `continueUrl`로 자동 이동하지 않는다.

2026-11-09 전용 사이트 배포와 실제 브라우저의 잘못된 링크 처리를 확인했다. 당시 관리 API와 콘솔에서 작업 URL 변경이 `EMAIL_TEMPLATE_UPDATE_NOT_ALLOWED`로 거절됐으나, 사용자가 이후 Firebase Console의 작업 URL 맞춤설정에 `https://fishingbuild-password-reset.web.app/`를 저장했다고 확인했다. 새 사이트의 인증 허용 도메인도 등록했다.

작업 URL 설정 완료와 실제 메일 경로 검증은 구분한다. 설정 변경 후 새로 발송한 메일이 전용 웹 화면을 여는지, 비밀번호 변경 후 앱 재로그인이 가능한지 확인해야 한다. 이번 develop 병합 중에는 메일 발송·계정 비밀번호 변경·Hosting 배포를 실행하지 않았다.

## 자동 검증

2026-11-09 초기 구현 검증에서 전체 Flutter 테스트 **1,266개 통과**, 전체 코드 분석 이상 없음. 신규 44개 테스트에서 SDK 위임·오류 분류, 이메일 검증, 세션·요금제·DB 보존, 계정 존재 여부 비공개 안내, 중복 요청·60초 대기, 재시도, 화면 종료·로그인 복귀를 검증했다. 기존 물때 테스트 한 건은 자동 물때와 수동 입력이 우연히 같아지는 날짜 의존성을 없애도록 입력 자료만 보정했다. 새로고침 추가 후에는 재설정 화면 테스트 12개를 통과했으며, 변경 이메일 유지·자동 전송 없음·이전 타이머 취소·전송 중 새로고침 차단을 확인했다.

최종 영문 대소문자 무관 정책 적용 후 전체 Flutter 테스트 **1,279개**, 재설정 웹 화면 Node 테스트 **13개**를 통과했다. 전체 Dart 코드 분석 이상 없음. 웹 테스트는 영문만·숫자만·짧은 비밀번호 차단, 대소문자 허용, 링크 종류 확인, 중복 요청, 오류·재시도, 브라우저 fetch 수신자와 다른 이메일 작업의 고정 주소 연결을 검증한다. 배포 화면은 실제 Chrome에서 잘못된 링크를 표시하고 입력을 차단하는 것까지 확인했다. 실제 계정의 비밀번호를 변경하거나 메일을 발송하는 테스트는 수행하지 않았다.

- 전체 Flutter 테스트 1,353개 중 1,350개 통과·3개 실패. 실패는 develop 감사에서 확인한 기존 앱 정보·출처 테스트와 동일하다.
- 실제 새 메일 발송·호스팅된 링크를 통한 비밀번호 변경·앱 재로그인은 아래 기기 확인 대상으로 남겼다.

## 실제 기기 테스트

1. Firebase 이메일 회원으로 기록을 저장하고 로그아웃한다. 로그인 화면에 이메일을 입력하고 **비밀번호를 잊으셨나요?**를 누르면 같은 이메일이 표시되어야 한다.
2. 빈 값·이메일 형식이 아닌 값을 제출하면 입력 안내가 나와야 한다. 올바른 이메일로 요청하면 확인 안내와 60초 대기가 표시되어야 하며 연속 누르기로 여러 요청을 보내지 않아야 한다.
3. 받은편지함·스팸함의 **새로 요청한 재설정 메일**을 열고, 영문만·숫자만·8자 미만 비밀번호가 거부되는지 확인한다. `password1`·`PASSWORD1`처럼 영문 대소문자 중 하나와 숫자를 포함한 8자 이상 비밀번호는 설정할 수 있어야 한다. 비밀번호 확인 값도 일치해야 한다. 변경 후 앱으로 돌아와 새 비밀번호로 로그인하면 기존 닉네임·요금제·기록이 유지되어야 한다. 이전 비밀번호로는 로그인에 실패해야 한다.
4. 다른 등록되지 않은 이메일에도 같은 확인 안내가 표시되어야 한다. 네트워크를 끈 경우 오류 안내가 나오고 복구 후 다시 요청할 수 있어야 한다.
5. 전송 후 이메일을 고치고 상단 새로고침을 누르면 고친 이메일을 유지하면서 안내와 대기 시간을 초기화해야 한다. 다시 전송 버튼을 누를 때만 새 주소로 요청해야 한다. 전송 중에는 새로고침을 누를 수 없어야 한다.
6. 전송 중 뒤로가거나 성공 후 화면을 닫았다 다시 열어도 오류가 없어야 한다. 이메일을 고친 뒤 로그인으로 돌아가면 수정한 이메일이 반영되어야 한다.

자동 테스트는 가짜 인증 어댑터와 SDK 대역을 사용한다. 실제 메일 도착·호스팅된 링크·여러 기기 세션 만료는 위 기기 테스트에서 확인한다. action URL 변경 이전에 발송된 메일은 이전 Firebase 기본 화면을 열 수 있으므로 새 메일을 요청한다.
