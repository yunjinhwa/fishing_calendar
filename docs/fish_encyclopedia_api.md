# 키 없이 사용하는 어류도감

도감의 기본 목록은 앱에 포함된 국립수산과학원 공개 자료로 표시한다. 첫 설치에 인터넷이 없거나 `fish.local.json`을 실행 옵션으로 전달하지 않아도 사용할 수 있다. 사진·설명은 Wikidata·한국어 위키백과·Wikimedia Commons를 우선 사용하고, 누락된 사진은 iNaturalist, 바뀐 학명은 GBIF의 현재 Catalogue of Life XR에서 확인해 보완한다. 이 추가 경로에는 별도 API 키가 필요하지 않다. 선택적으로 국립해양생물자원관 MBRIS의 한국어 설명을 함께 받아 보강한다. 기본 실행에서 NARIS를 호출하지 않는다.

## 기본 목록

`assets/data/fish_catalog.json`에는 2026-11-04 국립수산과학원 생물종정보에서 실제 조회한 800종의 국문명·학명·분류·별칭·서식 수역을 포함했다. 원본 997항목 중 국문명이 있는 항목이며 바다 673종, 민물 127종이다. 사진·설명을 지어낸 샘플 목록이 아니다. 출처·수집 시각도 파일에 포함하고 인증키와 계정 정보는 포함하지 않는다. 자료 크기는 약 375KB다.

원본은 [국립수산과학원 생물종정보 OPENAPI](https://www.nifs.go.kr/openApi/actionOpenapiInfoList.do)의 `https://www.nifs.go.kr/api/OpenAPI_json`에서 조회했다. `frcenterCode2`의 어류 분류를 확인하고 `frcenterInfo2`로 해당 어류만 받는다. 실제 분류 응답은 하위 배열을 포함하므로 분류 1회·어종 1회 요청으로 조회한다. 척추동물 전체를 어류로 간주하지 않는다.

`BTBS-WK-01 = 해수`, `BTBS-WK-02 = 육상 담수`는 [공식 생물종 정보의 코드·명칭 응답](https://www.nifs.go.kr/portal/bt/frctA/selectSpeciesList.do?largeClass=LV&midClass=FS&selectPage=1&pageUnit=3)에서 확인한 대응표다. 검증하지 않은 다른 코드는 미분류로 두고 전체 목록에만 표시한다. 생물명으로 수역을 추측하지 않는다.

검색은 앱이 가진 이름·학명·별칭을 대상으로 수행한다. 검색과 바다·민물 필터 판정에는 목록 조회 API가 필요하지 않다. 새로 화면에 보이는 어종의 사진은 아래의 별도 경로로 자동 조회한다. 기본 목록은 수집 시점의 자료이므로 앱 업데이트나 개발자의 자료 갱신으로 최신화한다.

## 목록 사진 자동 표시

상세 화면을 방문하지 않은 어종도 목록에서 사진을 자동으로 조회한다. 현재 화면에 보이는 행과 바로 인접한 행만 대상으로 삼고, 동시에 최대 두 어종을 처리한다. 화면 밖으로 나가거나 검색·필터에서 제외된 행의 대기 요청은 취소하며, 숨겨진 탭·다른 화면·오프라인 상태에서는 새 요청을 시작하지 않는다. 이미 진행 중인 요청은 공용 캐시에 결과를 남길 수 있다.

목록 사진은 Wikimedia를 우선 사용하고, 없으면 iNaturalist와 검증된 학명 보정 경로를 확인한다. 사진을 표시하기 위해 MBRIS의 전체 설명을 요청하지 않는다. 학명·명칭과 이용조건 검증은 상세 조회와 동일하게 유지하며, 검증된 사진이 없는 경우 기본 아이콘을 표시한다. 사진이 도착하면 해당 행만 갱신하고 800종 목록 전체를 다시 조회하지 않는다. 사진 정보가 있는 행은 즉시 재사용하며, 상세 화면을 열 때도 방금 받은 정보를 전달한다.

사진 메타데이터와 조회 실패는 기존 공개 도감 캐시에 별도로 보존한다. 사진이 실제로 없는 경우 6시간, 일시 실패는 30초 동안 자동 중복 조회를 줄인다. 제공처 구성이 달라지면 이전 사진 없음 캐시는 즉시 재확인하며, 과거에 받은 유효한 사진은 유지한다. 수동 새로고침은 화면에 보이는 사진 없는 행을 다시 확인할 수 있다. 설명용 캐시의 갱신 시각·자료원 구성과 기존 한국어 설명·크기를 사진 조회만으로 덮어쓰지 않는다.

Wikimedia 제공처에는 최대 128개·5분의 짧은 성공 캐시와 같은 요청의 공유 처리를 두어, 목록 사진을 받고 곧바로 상세 화면을 열 때 같은 Wikimedia 조회를 반복하지 않도록 했다. 사진 원본 파일을 DB에 저장하지 않으며 표시 크기에 맞춰 메모리 사용을 제한한다. 이미지 다운로드 자체는 인터넷 연결이 필요하다.

## 사진·설명

- [Wikidata API](https://www.wikidata.org/w/api.php)에서 학명 `P225`와 한국어 명칭을 확인한 자료만 연결한다. 같은 이름의 다른 생물이나 금붕어 같은 사육 품종을 붕어 사진으로 표시하지 않는다.
- 감성돔처럼 한국어 문서가 기본아종에 연결된 경우는, 아종명이 대상 종소명을 반복하는 기본아종이고 `P171`이 검증한 대상 종을 직접 가리키는 경우에만 허용한다. 그 밖의 비슷한 학명·동의어·상위 분류를 임의로 대신 사용하지 않는다.
- 한국어 위키백과 문서는 해당 분류 항목과 연결된 문서의 도입부를 사용한다. 검증된 학명과 어종명이 맞지 않거나 문서가 없으면 해당 설명을 제공되지 않음으로 표시한다.
- 한국어 문서가 없어도 유일한 학명·종 단계가 확인되고 한국어 명칭 충돌이 없으면 Commons 사진을 따로 조회한다. 한국어 이름을 확인할 수 있는 경우 라벨·별칭도 대조한다. 설명 없음이 사진 없음으로 이어지지 않도록 분리했다.
- 대표 사진은 검증한 분류 항목의 Commons 파일을 사용한다. 원본 파일의 작가·파일 페이지·이용허락 정보를 확인해 데이터로 보존한다. 이용조건을 확인하지 못한 사진이나 비영리 이용만 허용된 사진은 연결하지 않는다.
- 사진·설명 조회가 실패해도 기본 목록·학명·분류·수역과 기록 작성 기능은 사용할 수 있다. 자료가 없는 것을 연결 설정 누락이라고 표시하지 않는다. 금어기·금지 체장은 별도 후속 작업이며 자료 없음이 금어기 없음이라는 뜻은 아니다.
- 통신·시간 초과·호출 제한은 실제 자료 없음과 구분한다. 부분 정보는 유지하고 상세 화면의 `상세 정보 새로고침`으로 바로 다시 받을 수 있다.
- 원본 사진 비율을 유지한다. 사용자 요청에 따라 도감 목록·상세의 작가·출처·이용허락 표시는 제거하고, 별도 출처 화면에 사용할 수 있도록 모델·캐시에 관련 정보와 링크를 보존한다. 별도 출처 화면 연결은 후속 작업이며 기존 라이선스 안내 자료는 유지한다.

공식 안내: [Wikimedia API 이용 정책](https://www.mediawiki.org/wiki/Wikimedia_APIs/Access_policy), [MediaWiki Action API](https://www.mediawiki.org/wiki/API:Main_page), [Commons 이미지 정보 API](https://www.mediawiki.org/wiki/API:Imageinfo).

## 누락 정보 보완

검증한 공개 정보는 `assets/data/fish_enrichment.json`에도 포함한다. 전체 800종을 대조한 결과, 첫 목록을 읽을 때 한국어 설명 588종·실제 사진 연결 431종·크기 282종·상세 서식지 14종을 사용할 수 있다. 설명·서식지는 오프라인에서도 읽을 수 있지만 원격 이미지 파일의 최초 다운로드에는 인터넷이 필요하다. 전체를 확인했어도 모든 종의 모든 항목이 채워진 것은 아니다. 어종별 제공 여부와 검증 경로는 [전체 자료 현황](fish_enrichment_inventory.json), 자동 수집·생성 방법은 [제공 범위](fish_data_coverage.md)에 기록한다.

갈치처럼 대표 사진의 이용조건 때문에 기존 경로에서 비어 있던 항목은 국립수산과학원의 개별 공공누리 제1유형 사진으로 보강한다. 수집 시 국명·학명·구역별 이용조건이 모두 일치해야 하며 원본 사진과 워터마크를 유지한다. 공식 사진 경로에서 11종을 추가했고, 이전의 사진 없음 캐시도 새 번들 사진을 가리지 않는다. 사진 출처와 이용조건은 모델·번들에 보존하며 기존 요청대로 목록·상세 화면에는 표시하지 않는다.

자료는 어종별로 코드를 추가하는 대신 API 전체 수집·종 연결 검증·자료 병합으로 생성한다. MBRIS의 국내·해외 분포도 포함한다. 한국어 문서가 없는 어종의 사진도 놓치지 않도록 영어 문서를 사진 전용으로 대조하되, 영어 원문을 번역한 것으로 표시하지 않는다. 더 자세한 설명으로 바뀌어도 다른 자료원에서 이미 확인한 크기를 지우지 않으며 출처와 원문 발췌를 별도 보존한다.

기존 기기의 최신 캐시가 비어 있어도 번들 보강 자료를 함께 표시한다. 기존에 유효한 설명·사진·크기는 보존하고 빈 값만 채우며 기본 국명·학명·분류·별칭은 바꾸지 않는다. 보강 자료 파일은 서비스당 한 번만 읽고, 파일이 없거나 손상되어도 기본 목록은 계속 사용할 수 있다. 설명과 사진을 모두 포함하고 확인 후 7일이 지나지 않은 보강 프로필은 일반 상세 진입 시 원격 요청을 생략하며, 수동 새로고침은 원격 조회를 수행한다. 사진 없는 종은 기존의 누락 사진 조회 경로를 유지한다.

일시적으로 일부 정보를 받지 못한 경우에는 `일부 정보를 불러오지 못했습니다.`와 재시도 동작을 표시한다. 확보하지 못한 설명·사진을 단순한 자료 없음과 구분하며, 이미 표시한 정보는 유지한다. API 출처와 작가 정보는 기존 요청대로 목록·상세 화면에 표시하지 않는다.

실제 사진만 사용한다는 요청에 따라 명시적인 삽화·수채화·지도·AI 생성물은 파일명과 Commons 설명 메타데이터에서 제외한다. 같은 판단을 캐시 복원·목록 사진 조회·상세 사진 표시에 적용해 기존에 저장한 삽화도 사진으로 표시하지 않는다. 이 필터는 메타데이터 기반이며, 공개 파일의 내용 전체를 자동 판독하는 기능은 아니다.

구조화된 대표 사진 링크가 없었던 가라지·가숭어·가시가자미는 실제 파일을 내려받아 내용·국명·학명·작가·라이선스를 직접 확인한 [검수 사진 목록](../lib/data/fish/reviewed_fish_photos.dart)에 추가했다. 목록 사진은 상세 설명 조회 없이 연결되며 별도 사진 API 키가 필요하지 않다. 가시가자미는 보존 표본의 실제 사진과 방사선 사진을 함께 보여 주는 원본 도판이다. 기존의 유효한 실제 사진과 설명은 덮어쓰지 않는다. 사진이 없는 종을 다른 종의 사진이나 그림으로 대신 채우지 않는다.

기존에 유효한 설명·사진·크기는 보존하고 비어 있는 항목만 다음 순서로 보완한다. 원래 목록의 식별자·국명·학명을 다른 자료원의 값으로 바꾸지 않는다.

1. Commons 대표 사진이 없거나 사용할 수 없으면, 검증된 분류 항목의 `P373` 또는 Commons 분류 링크에서 최대 4개 파일을 확인한다. 분류에 속한다는 이유만으로 사진을 고르지 않고, 해당 파일의 MediaInfo `P180`이 정확히 대상 어종만 가리키는지 확인한다. 하위 분류와 다음 페이지는 순회하지 않는다. [Categorymembers API](https://www.mediawiki.org/wiki/API:Categorymembers), [MediaInfo JSON](https://www.mediawiki.org/wiki/Extension:WikibaseMediaInfo/Data_Model/JSON)
2. 그래도 사진이 없으면 iNaturalist에서 학명이 정확히 같은 유일한 활성 종의 분류군 사진을 확인한다. 한국어 명칭 충돌·표시된 문제·다른 종 연결·미확인 이용조건은 거부한다. CC0·CC BY·CC BY-SA 사진만 사용하고 작가·원본 페이지·이용허락을 보존한다. 최대 2회 요청·전체 10초·요청 간 1초 간격과 성공 캐시를 적용한다. [API 이용 지침](https://www.inaturalist.org/pages/api+recommended+practices), [사진 이용 안내](https://help.inaturalist.org/en/support/solutions/articles/151000169918)
3. GBIF v2에서 현재 COL XR 체크리스트를 지정해 원래 학명이 명시적 동의어인지 확인한다. 기존 학명과 정식 학명을 최대 2회 정확히 조회하고 어류·종 단계·과·정명 식별자가 일치할 때만 후보 하나를 허용한다. 유사 검색·동명이종·모호한 결과·종과 아종 간 임의 변환은 거부한다. 후보 학명으로 다시 받은 새 한국어 설명이 국명까지 확인한 경우에만 결과를 합친다. GBIF의 동의어 관계만으로 이름이 다른 사진을 허용하지 않는다. [GBIF Species API](https://techdocs.gbif.org/en/openapi/v1/species), [분류 처리와 체크리스트](https://techdocs.gbif.org/en/data-processing/taxonomy-interpretation)

추가 조회는 공통 12초 복구 예산을 사용한다. 남은 시간으로 Wikimedia·MBRIS 재조회 범위를 제한하고 원격 제공처의 취소 처리를 적용한다. 모든 필요한 항목이 채워지면 부분 실패 재시도 표시를 해제해 불필요한 30초 재조회를 줄인다. 검증된 자료가 끝내 없으면 기존 제공되지 않음 표시를 유지한다.

한국어 자료가 없었던 가는곰치·가시전갱이·가시줄고기·각시가자미에는 영어 위키백과의 학명·종 단계·문서 연결을 확인한 뒤 한국어 번역·요약을 포함했다. 특정 문서 개정판과 CC BY-SA 4.0 및 번역 사실을 메타데이터로 보존한다. 기존 한국어 설명은 덮어쓰지 않으며, 국명과 학명이 모두 일치할 때만 적용한다. 크기는 설명에 길이와 단위가 명시된 경우에만 원문 문구로 보완하며 새로운 수치를 추정하지 않는다. 실행 중 번역 서비스는 호출하지 않는다. 원문 링크와 개정판은 [번역 보완 코드](../lib/data/fish/bundled_fish_descriptions.dart)와 라이선스 안내에 있다. 기본 목록 JSON의 원본 데이터는 그대로 유지한다.

## MBRIS 한국어 설명 보강

[국립해양생물자원관_해양생물종정보 서비스](https://www.data.go.kr/data/15094770/openapi.do)의 활용 신청이 승인되면 프로젝트 최상위 `fish.local.json`의 `MBRIS_SERVICE_KEY`에 공공데이터포털 일반 인증키(Decoding)를 입력한다. 기존 NIFS·NARIS 항목은 그대로 두고 새 항목을 채운다. NARIS에서 발급한 키를 사용하는 서비스가 아니다.

```json
{
  "NIFS_SPECIES_API_KEY": "기존 값 유지",
  "NARIS_API_KEY": "기존 값 유지",
  "MBRIS_SERVICE_KEY": "공공데이터포털 Decoding 인증키"
}
```

실행 명령에 `--dart-define-from-file=fish.local.json`을 추가하고 앱을 완전히 다시 실행한다. 키가 없을 때는 MBRIS를 호출하지 않고 기존 키 없는 조회를 사용한다. 키를 채팅·예제 파일·로그에 넣지 않는다.

MBRIS `taxonlist3`의 `ABST`(개요), `FORM`(형태), `ECOL`(생태), `HABI`(서식지)를 국문명·학명이 일치하는 경우에만 사용한다. 다른 정명으로 연결되는 항목과 서로 충돌하는 결과는 자동으로 합치지 않는다. 페이지를 끝까지 확인할 수 없는 응답도 자료 없음으로 저장하지 않는다.

MBRIS와 Wikimedia는 독립적으로 조회하며, 한국어 설명은 유효한 MBRIS 내용을 우선하고 사진은 Wikimedia의 검증된 파일을 사용한다. 한쪽 서비스의 실패로 다른 쪽에서 받은 정보를 지우지 않는다. 크기는 아래 규칙에 따라 검증된 설명에서 보완한다.

요청 전체 12초, 응답 2MiB와 페이지 수 제한을 적용한다. XML은 이미 프로젝트에 설치되어 있던 `xml 6.6.1`을 직접 의존성으로 선언해 처리하며 해당 버전은 변경하지 않았다. 2026-11-05 승인된 키의 실제 정상 응답을 확인했고, 저자명이 포함된 학명은 응답의 명시적 `SpcScitfNmShort`로 대조하도록 반영했다. 전체 800종의 제공 범위는 별도 일괄 점검이 필요하다. 명세에 필드가 있다는 사실만으로 모든 어종에 값이 있다고 판단하지 않는다.

## 크기 표시

크기에는 일반 몸길이와 최대 길이를 모두 표시하되, 원문의 표현을 보존한다. 예를 들어 `몸 길이는 5~7cm`와 `수컷의 최대 전장은 약 10cm`를 같은 의미로 바꾸지 않는다. 전장·체장·표준체장·가랑이체장, 성별·성장 단계, 범위·소수·단위도 보존하며 단위 변환이나 최대값 계산은 하지 않는다.

MBRIS의 검증된 개요·형태·생태 설명과 한국어 위키백과·검수된 한국어 보완 설명에서 명확한 몸길이 문장만 선택한다. 수심·체중·지느러미·알·먹이의 크기, 부정된 값·단위 누락·모호한 문장은 크기로 사용하지 않는다. 긴 설명에서도 최대 3개 원문 문장 또는 절, 총 450자까지 표시한다. 이미 제공된 크기 값이 있으면 유지한다. 크기 자료가 없을 때는 기존 `제공되지 않음`을 유지한다.

기존 캐시를 읽을 때도 설명으로 크기를 복원한다. 추가 API 요청·캐시 시각 갱신·강제 원격 새로고침 없이 오프라인에서도 적용되며, 상세 정보를 불러오기 전과 조회 실패 시에도 현재 설명에 명시된 길이를 확인할 수 있다. 내부 캐시의 `maxSize` 문자열 키는 호환성을 위해 유지하지만, 일반 길이도 원문의 구분을 포함한 문자열로 저장한다. SQLite·Firestore 스키마나 회원 데이터는 변경하지 않는다.

2026-11-06 보관한 동일 20종 설명만 로컬로 재처리하여 10종에서 크기 표시를 확인했다. 원문에 적힌 몸길이를 추출한 결과이며 새 실서비스 조회나 전체 800종의 크기 제공 여부 점검은 아니다. 결과는 `.dart_tool/fish_size_coverage_check.json`에 기록했다.

## 실행

기본 도감에는 추가 키가 필요하지 않다. 기존 지도·날씨·조석 설정을 그대로 전달한다.

```powershell
& "C:\flutter\bin\flutter.bat" run --dart-define=FIREBASE_AUTH_ENABLED=true --dart-define-from-file=kakao.local.json --dart-define-from-file=weather.local.json --dart-define-from-file=tide.local.json
```

목록 파일과 실행 코드가 바뀌었으므로 기존 실행을 종료하고 다시 실행한다. `fish.local.json`과 `NARIS_API_KEY`는 기본 도감 실행에 필요하지 않다. 기존 로컬 파일은 Git에서 계속 제외하고 삭제하지 않는다.

## 선택적인 NIFS 갱신

NIFS 인증키가 있으면 기본 목록을 유지하면서 개발 중에 원격 갱신할 수 있다. `fish.local.json`의 `NIFS_SPECIES_API_KEY`에 기존 키를 넣고 실행 명령에 `--dart-define-from-file=fish.local.json`을 추가한다. 키가 있는 실행의 도감 새로고침만 NIFS를 호출한다. 키가 없으면 기본 목록을 다시 읽고, 원격 갱신이 실패해도 사용 가능한 기본 목록이나 이전 결과를 유지한다.

다음 앱 버전에 포함할 공개 목록은 프로젝트 최상위에서 갱신한다.

```powershell
& "C:\flutter\bin\dart.bat" run tool/update_fish_catalog.dart
```

이 명령만 로컬 NIFS 키를 읽으며, 갱신 결과에는 공개 어종 데이터와 출처·수집 시각만 저장한다. 실행 전에 해당 키가 설정되어 있어야 한다. 변경한 자료는 일반 소스 파일과 함께 검토·커밋할 수 있다. `fish.local.json`은 커밋하지 않는다.

NARIS 직접 연동 코드는 추후 필요할 때 검토할 수 있도록 남겨 두었지만 기본 조회 경로에서는 사용하지 않는다. 공공데이터포털의 [국립중앙과학관 국가자연사연구종합정보](https://www.data.go.kr/data/15061794/openapi.do)는 같은 NARIS로 연결하는 링크형 등록이며 별도의 우회 인증 서비스가 아니다.

## 캐시와 접근

도감 탭을 처음 선택할 때 목록을 읽고, 숨겨진 탭에서는 요청이나 로딩 애니메이션을 시작하지 않는다. 저장한 목록은 24시간, 설명·사진이 모두 있는 상세는 30일, 일부만 있는 상세는 6시간 캐시한다. 통신 장애로 일부를 받지 못한 결과는 30초 뒤 다시 조회할 수 있다. 실제 재조회는 화면 진입·수동 새로고침 시 수행하고 백그라운드 반복 타이머를 만들지 않는다. 제공처 구성이 바뀌면 새 제공처로 상세를 다시 보강하며 오프라인에서는 기존 결과를 유지한다.

같은 상세의 진행 중 요청은 공유한다. 상세는 최대 128종, 기기에 저장하는 전체 JSON은 최대 4MiB로 제한한다. 이미지 파일을 DB에 저장하지 않는다. 기본 자료의 수집 시각과 기기의 캐시 접근 시각을 구분한다.

인터넷이 없는 첫 설치에서도 앱에 포함한 목록을 읽는다. 이미 받은 상세는 오프라인에서 표시하고 아직 받지 않은 설명·사진은 제공되지 않음으로 안내한다. 연결 복구 시 실패한 상세를 다시 조회할 수 있다. 공개 도감 캐시는 회원의 출조 기록·Outbox·Firestore와 별개이며 SQLite·Firestore 스키마와 보안 규칙은 바꾸지 않는다.

비회원도 도감을 볼 수 있다. `이 어종으로 기록 작성하기`는 기존 회원 접근 제한을 적용하며 회원에게는 선택한 어종명을 기록 작성 화면에 전달한다.

## 기기 테스트

이번 보강은 앱을 완전히 종료하고 다시 실행해 적용한다. 데이터 삭제나 재설치는 필요하지 않다. 먼저 감성돔·넙치·참돔·쏘가리의 목록 사진과 상세 설명을 확인한다. 붕어·잉어는 사진이 없어도 한국어 설명과 상세 서식지가 보여야 하며, 붕어의 크기는 일반 몸길이와 큰 개체 조건이 함께 유지되어야 한다. 비행기 모드에서도 보강 설명은 보이고, 아직 내려받지 않은 사진은 정상 아이콘으로 남아야 한다. 상세의 수동 새로고침과 기존 기록 작성 연결도 확인한다.

1. 실행을 종료한 뒤 위의 명령처럼 `fish.local.json` 없이 다시 실행한다. 도감 탭에 800종 목록이 나오고 바다·민물 필터와 이름·학명·별칭 검색이 동작해야 한다.
   아직 상세 화면을 방문하지 않은 어종을 검색하고 잠시 기다리면 목록의 사진이 자동으로 표시되어야 한다. 자료가 없는 어종은 기본 아이콘을 유지한다. 빠르게 스크롤하거나 검색어를 바꾸어도 이전 행의 사진이 다른 어종에 붙으면 안 된다.
2. 비행기 모드에서도 목록이 표시되어야 한다. 처음 본 상세의 추가 정보가 없더라도 기본 정보와 기록 작성 버튼은 남아 있어야 한다.
3. 넙치·감성돔 등 상세를 열어 제공되는 설명·사진이 해당 어종인지, 사진 비율이 유지되고 목록·상세에 출처나 이용허락 링크가 노출되지 않는지 확인한다. 모든 어종에 설명과 사진이 있다고 보장하지 않는다.
4. 붕어처럼 제공처 사이의 국명·학명이 다를 수 있는 항목에 다른 어종·품종 사진을 무리하게 연결하지 않는지 확인한다.
5. 비회원의 기록 작성은 로그인 안내로 이동하고, 회원의 기록 작성에는 선택한 어종명이 채워져야 한다.
6. 화면 전환·빠른 검색·오프라인 전환·다시 연결·앱 재실행 뒤에도 목록과 기존 정보가 유지되는지 확인한다.
7. 가시납지리를 검색해 상세를 열지 않아도 목록 사진이 내려오는지 확인한다. 가는곰치·가시전갱이·가시줄고기·각시가자미의 상세에서 한국어 설명을 확인한다. 이미 실행 중인 앱은 완전히 다시 시작하고, 과거 캐시가 보이면 상세 새로고침을 사용한다. 추가 API 키를 발급받을 필요는 없다. 실제 자료 제공 여부는 제공처 변경과 네트워크 상태에 따라 달라질 수 있다.
8. 가라지·가숭어·가시가자미의 사진이 목록에서 상세 진입 없이 표시되는지 확인한다. 과거에 수채화가 보였던 항목은 실제 사진이 확보된 경우 사진으로 바뀌고, 확보되지 않았다면 기본 아이콘을 유지해야 한다. 가시가자미는 실제 표본 사진과 방사선 사진으로 된 원본 도판이며 사진 전체를 표시한다.
9. 앱의 변경 사항을 반영해 상세 화면의 `크기`를 확인한다. 설명에 몸길이가 있는 어종은 해당 문구가 표시되고, 최대 길이·성별·전장·체장 같은 조건이 유지되어야 한다. 가시줄고기의 한국어 보완 설명에는 수컷 최대 전장 약 10cm가 있어 오프라인에서도 크기에 표시된다. 기존에 저장된 설명도 적용되며 설명과 크기에 다른 수치가 새로 생성되지 않아야 한다.
