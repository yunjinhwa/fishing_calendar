# 인증 요청 경합 방어

브랜치: `fix/auth-operation-race` · 대상: [최초 감사](pre-release-audit.md)의 A-01.

## 수정한 문제

가입이 Firebase 계정 생성 후 닉네임 검사에서 대기하는 동안 다른 계정으로 로그인하면, 앞선 가입의 실패 정리가 나중에 로그인한 계정을 삭제 대상으로 잡을 수 있었다. 로그인 실패 후의 로그아웃 정리도 새 세션을 종료할 수 있었다.

닉네임 확인뿐 아니라 계정 정보 적용과 SharedPreferences 저장까지 여러 await가 이어지므로, 마지막 삭제 직전의 UID 비교만으로 전체 작업의 경합을 막을 수는 없다.

## 처리 방식

- `AuthSessionRepository`에서 세션 복원·로그인·가입·비회원 전환·로그아웃·비밀번호 변경·탈퇴 중 하나만 실행한다. Firebase 호출, 로컬 세션 저장, 실패 정리가 모두 끝난 후 제한을 해제한다.
- 처리 중 추가 인증 요청은 대기열에 쌓지 않고 `operationInProgress`로 거절한다. 오류가 발생한 경우에도 finally에서 제한을 해제하여 다음 요청을 받을 수 있게 한다.
- `deleteCurrentUser(expectedUid: ...)`는 현재 UID가 작업에서 캡처한 UID와 일치할 때만 삭제한다. 로그인·가입 실패 정리의 로그아웃도 해당 UID가 여전히 현재 사용자일 때만 수행한다.
- 세션 설정의 주요 비동기 경계에서 현재 Firebase 사용자와 게이트웨이를 확인한다. 표시 이름 갱신이 다른 UID를 반환하면 원래 이메일과 결합하여 세션을 저장하지 않는다.
- 인증 처리 중에는 게이트웨이 재설정을 허용하지 않는다. 원격 탈퇴 표식에 따른 기존 로컬 정리 콜백은 인증 제한을 재진입하지 않도록 유지한다.

네이티브 Firebase 로그인 요청은 시작 후 취소할 수 없으므로, 실행 중인 요청을 남겨 둔 채 새 로그인으로 넘어가지 않도록 구성했다.

## 화면 동작

- 로그인·가입 처리 중 뒤로 이동과 다른 인증 화면으로의 전환을 막는다. 정상 완료에 따른 화면 전환은 유지한다.
- 로그인·가입 버튼을 연속 호출해도 같은 화면에서 중복 제출하지 않는다.
- 로그인 선택 화면은 저장소의 처리 상태를 구독하여 로그인·회원가입·비회원 버튼을 비활성화한다. 비회원 전환도 중복 실행을 막는다.
- 실패하면 안내를 표시하고 버튼과 뒤로 이동을 다시 사용할 수 있다. 비밀번호를 누르는 동안 표시하는 기존 기능은 유지한다.

## 실제 기기 확인

테스트 계정으로 다음 항목을 확인한다.

1. **로그인 대기와 복구:** 로그인 버튼을 여러 번 누르고, 처리 중 뒤로 이동·회원가입 전환을 시도한다. 다른 화면으로 이동하지 않아야 한다. 잘못된 비밀번호 등의 실패 후에는 버튼·뒤로 이동이 복구되고 정상 계정으로 다시 로그인할 수 있어야 한다.
2. **가입 실패와 기존 계정 보존:** 새 테스트 이메일에 이미 사용 중인 닉네임으로 가입을 시도한다. 처리 중 로그인 링크·뒤로 이동이 막히고, 중복 닉네임 안내 후 다시 사용할 수 있어야 한다. 기존 닉네임 소유 계정으로 로그인하여 기존 계정·기록이 유지되는지 확인한다.
3. **정상 흐름:** 정상 가입·로그인 후 앱 화면으로 이동하고, 로그아웃·비회원 시작·앱 재실행을 확인한다. 비회원 시작을 연속으로 눌러도 화면 전환은 한 번이어야 한다. 기록 작성에서 로그인 안내를 통해 열린 경우에도 정상 완료 후 이전 화면으로 돌아와야 한다.

네트워크가 빠르면 처리 중 상태가 짧게 보인다. 응답 순서를 정밀하게 지연시키는 조건은 위 자동 테스트에서 검증했다.
