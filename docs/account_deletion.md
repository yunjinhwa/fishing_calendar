# 회원 탈퇴 처리 정책

현재 앱은 별도 백엔드나 Cloud Functions 없이 Firebase 클라이언트 SDK로 회원 탈퇴를 처리한다. 이 문서는 첨부 API 명세의 `WITHDRAWN` 논리 삭제 모델과 구분되는 현재 프로토타입 정책을 기록한다.

## 처리 순서

1. 사용자가 현재 비밀번호와 `탈퇴` 확인 문구를 입력한다.
2. Firebase Authentication으로 비밀번호를 재확인한다. 재확인 실패 시 어떤 데이터도 변경하지 않는다.
3. `account_deletion_requests/{uid}`에 불변 삭제 표식을 만든다. Firestore 규칙과 실행 중인 앱의 실시간 구독이 이 표식을 감지해 모든 기기의 일반 기록 생성·수정·동기화를 차단한다. 다른 기기는 비밀번호를 다시 요구하지 않고 해당 UID의 SQLite 기록, Outbox, 동기화 상태, 충돌 데이터, 사진과 계정 캐시를 자동 정리한다.
4. `users/{uid}/records`, `users/{uid}/sync_receipts`, `plan_entitlements/{uid}`를 삭제한다.
5. 재시작 복구용 로컬 cleanup 표식을 저장하고 해당 계정의 로컬 로그인 정보와 세션을 먼저 제거한다. 이어서 SQLite 기록, Outbox, 동기화 상태, 충돌 데이터와 계정 전용 사진 디렉터리를 삭제한다.
6. `user_profiles/{uid}`와 연결된 `nickname_claims`를 함께 삭제한다.
7. Firebase Authentication 계정을 삭제한다.

삭제는 각 단계가 여러 번 실행되어도 같은 결과가 되도록 구성한다. 앱이 중간에 종료되면 로컬 cleanup 표식으로 기기 데이터 정리를 재개한다. 정리 중 오류가 발생해도 앱 시작은 계속하고 표식을 보존해 다음 실행에서 다시 시도한다. 서버 삭제 표식이 있는 계정이 다시 로그인하면 일반 회원 기능을 열지 않고 회원 탈퇴 재개 상태로 진입한다.

기존 세션을 오프라인으로 복원할 때 삭제 표식을 서버에서 확인할 수 없으면 검증된 로컬 계정·요금제 캐시로 먼저 연다. 이때도 실시간 구독은 유지하므로 네트워크가 복구되어 표식이 확인되는 즉시 기능을 잠그고 로컬 정리를 시작한다.

## 보존되는 최소 데이터

`account_deletion_requests/{uid}`에는 다음 값만 남는다.

- Firebase UID
- 스키마 버전
- `REQUESTED` 상태
- 요청 시각

이 표식은 다른 기기나 오래된 인증 토큰이 데이터를 다시 만드는 것을 막기 위해 클라이언트에서 수정하거나 삭제할 수 없다. 이메일, 닉네임, 기록, 사진은 포함하지 않는다. 운영 백엔드를 도입하면 보존 기간에 따라 관리자 권한으로 정리해야 한다.

## 현재 한계

Firestore 컬렉션 삭제는 클라이언트에서 작은 배치로 수행하므로 전체 작업이 하나의 원자적 트랜잭션은 아니다. 네트워크가 끊기면 일부 삭제가 끝난 상태로 멈출 수 있으며, 사용자는 같은 계정으로 다시 인증해 나머지 작업을 완료해야 한다. 결제 및 운영 백엔드를 도입할 때는 Admin SDK에서 계정 상태 전환, 결제 권한 종료, 데이터 보존 기간, Firebase Auth 삭제를 함께 처리하는 방식으로 교체한다.

## 배포

앱으로 실제 탈퇴를 시험하기 전에 변경된 Firestore 규칙을 배포한다.

```powershell
npx firebase-tools deploy --only firestore:rules,firestore:indexes --project fishingbuild
```

규칙이 배포되지 않은 환경에서는 기록·동기화 영수증·entitlement의 물리 삭제가 거부되며 탈퇴가 완료되지 않는다.
