# 카카오 지도 연결

Android·iOS 앱에서 `kakao_map_plugin`의 WebView와 카카오 지도 JavaScript SDK를 사용한다. 장소·주소 검색, 지도 지점 선택, 현재 위치 확인 결과를 기록 작성 화면에 전달한다. 날씨·기온의 실제 예보 연결과 실행 옵션은 [날씨 API 연결](weather_api_setup.md)을 참고한다. 물때·수온은 수동 입력한다.

## 키와 도메인 설정

1. 카카오 Developers의 해당 앱에서 `카카오맵 → 사용 설정 → 상태 ON`으로 활성화한다. 서버가 `disabled OPEN_MAP_AND_LOCAL service`를 반환하면 이 설정을 먼저 확인한다.
2. **플랫폼의 JavaScript 키**를 사용한다. Native 앱 키, REST API 키, Admin 키를 입력하지 않는다.
3. 해당 JavaScript 키의 SDK 도메인에 `https://fishingbuild.firebaseapp.com`을 등록한다. 앱의 WebView가 사용하는 HTTPS 원점이며, Firebase Hosting 배포는 필요하지 않다.
4. 프로젝트 루트의 `kakao.example.json`을 `kakao.local.json`으로 복사하고 `KAKAO_JAVASCRIPT_KEY`에 키를 입력한다. `KAKAO_MAP_BASE_URL`은 등록한 HTTPS 원점과 일치시킨다.

`kakao.local.json`은 Git에서 제외된다. 예제 파일에는 실제 키를 넣지 않는다. JavaScript 키는 앱에 포함되는 클라이언트용 키이므로 카카오의 등록 도메인 제한을 적용한다.

```powershell
Copy-Item kakao.example.json kakao.local.json
# kakao.local.json 편집 후 실행
flutter run --dart-define=FIREBASE_AUTH_ENABLED=true --dart-define-from-file=kakao.local.json
```

이미 설정한 로컬 파일은 다시 복사하지 않는다. 키나 실행 옵션을 변경하면 앱을 완전히 종료하고 다시 실행한다. Hot Reload만으로는 컴파일 설정이 바뀌지 않는다. Android Studio에서도 같은 실행 옵션을 Additional run args에 넣는다.

설정이 없거나 Android·iOS 이외의 환경이면 직접 입력 화면을 이용할 수 있다. 인터넷이 끊기거나 지도 로딩이 실패하면 안내와 재시도 기능을 표시한다. 지도 준비는 15초, 검색·좌표의 주소 조회와 GPS 위치 획득은 각각 12초까지 기다린다.

## 동작과 권한

- 지도 탭을 열 때만 WebView를 만든다. 진입할 때 위치 권한이 이미 허용되어 있고 위치 서비스가 켜져 있으면 현재 위치를 한 번 조회한다. 같은 탭의 일반적인 화면 갱신에서는 GPS를 다시 조회하지 않으며, 다른 탭에 있으면 자동 조회하지 않는다.
- 장소 이름·주소를 검색하면 키보드가 닫히고 첫 번째 유효 결과로 지도와 선택 위치가 자동 변경된다. 결과 목록은 지도 아래에 표시하며, 다른 결과를 누르면 해당 위치를 선택한다. 결과가 없거나 조회에 실패하면 기존 위치를 유지한다. 지도에서 지점을 눌러 선택할 수도 있다.
- 자동 조회에서는 기존 권한만 확인하고 동의 창을 띄우지 않는다. 아직 권한이 없으면 기존 위치를 유지하며, 사용자가 `현재 위치`를 눌렀을 때 권한을 요청한다. Android의 대략적 위치도 사용할 수 있다.
- 권한 거절 시 검색·지도 지점 선택·직접 입력을 이용할 수 있다. 영구 거절이나 위치 서비스 꺼짐에는 해당 설정을 여는 버튼을 표시한다.
- 직접 입력은 장소 이름만 확정하고 기존에 선택했던 좌표를 제거한다. 이전 지점의 좌표가 다른 장소 이름에 남지 않는다.
- 지도와 지도 상세의 기록 작성 버튼은 장소명·좌표를 함께 전달한다. 비회원에게는 기존 로그인 안내를 표시한다.
- 이전 검색이나 주소 조회가 늦게 끝나도 나중에 선택한 위치를 덮어쓰지 않는다.
- 지도 탭을 떠나면 진행 중이던 위치 조회 결과를 무효화한다. 자동 GPS가 늦게 끝나도 그 사이 사용자가 검색하거나 직접 선택한 위치를 덮어쓰지 않는다.

Android에는 인터넷·전경 위치 권한, iOS에는 `NSLocationWhenInUseUsageDescription`을 설정한다. 백그라운드 위치 권한이나 전역 HTTP/ATS 허용 설정은 사용하지 않는다.

iOS의 Swift Package Manager 빌드에서는 geolocator의 Always 권한 코드를 제외하도록 빌드 환경 변수 `BYPASS_PERMISSION_LOCATION_ALWAYS=1`을 설정한다. 실제 iOS 빌드·권한 확인은 macOS에서 진행한다.

## 실제 기기 확인

1. 위 실행 옵션으로 앱을 실행하고 지도 탭을 연다. 실제 지도 타일이 나타나는지 확인한다. 이미 위치 권한을 허용했고 위치 서비스가 켜져 있으면 버튼을 누르지 않아도 현재 위치로 이동해야 한다. 다른 탭에 갔다가 돌아온 경우도 확인한다. 권한을 허용하지 않았다면 자동 동의 창이 나오지 않아야 하며, 다른 탭에 머무르는 동안에는 자동 조회하지 않는다.
2. `국동항` 같은 장소 이름과 도로명 주소를 각각 검색한다. 검색만으로 첫 결과의 위치로 이동하고 키보드가 닫히는지 확인한다. 지도 아래 목록에서 다른 결과를 눌렀을 때도 선택 장소와 지도 표시가 바뀌어야 한다. 없는 검색어에는 결과 없음 안내가 나오며 이전 선택 위치가 유지되어야 한다.
3. 지도에서 다른 지점을 누른 뒤 기록 작성으로 이동한다. 장소 이름과 `위도·경도 (선택)` 값이 같은 지점을 가리키는지 확인한다. 지도 상세를 거쳐 이동한 경우도 확인한다.
4. `현재 위치`를 눌러 권한 허용·거절을 각각 확인한다. 위치 서비스가 꺼진 경우와 영구 거절한 경우에는 설정 이동 버튼을 확인한다. 설정 변경 후 다시 `현재 위치`를 누른다.
5. 좌표가 있는 지점을 선택한 다음 `장소 직접 입력`으로 다른 이름을 입력한다. 기록 작성 화면의 두 좌표가 비어 있어야 한다.
6. 오프라인에서 직접 입력과 로그인한 회원의 기록 작성을 확인한다. 온라인 복구 후 지도 표시와 검색을 다시 확인한다.
7. 비회원도 지도를 보고 검색할 수 있지만 기록 작성 버튼에서는 로그인 안내가 나오는지 확인한다.

지도 로딩이 실패하면 JavaScript 키 종류·카카오맵 활성화·등록 SDK 도메인·앱 실행 옵션을 확인한다. 키 값이 로그나 Git 변경 목록에 포함되지 않도록 한다.

## 개발 중 검증 기록 (2026-11-02)

- 최초 지도 연동 검증에서 지도 관련 단위·위젯 테스트 49개, 전체 Flutter 테스트 483개 통과
- `flutter analyze --no-pub` 오류 없음
- 실제 로컬 설정을 사용한 Android debug APK 빌드·연결 기기 설치 성공
- 등록 원점을 사용한 카카오 SDK 스크립트 요청 HTTP 200 확인
- 연결 앱의 WebView에서 실제 SDK 조회 확인: `국동항` 장소 검색 6건, 도로명 주소 검색 1건 수신
- 검색 진행·결과 표시 중 지도 재생성으로 연결이 끊기는 문제를 회귀 테스트로 재현하고 수정했다. 지도 슬롯에 고정 키를 적용하고, 지도 탭이 활성화된 동안 화면 밖에서도 상태를 유지한다. 탭을 떠나면 지도 자원을 해제한다.
- 검색 수정 후 지도·접근 제한 관련 테스트 47개와 정적 분석 통과. 추가 회귀 테스트 2개는 검색 진행·결과 표시·스크롤 중 상태 유지와 탭 종료 시 자원 해제를 검증한다.
- 자동 위치 표시 추가 후 위치 게이트웨이·선택 컨트롤러·지도 화면 테스트 53개와 기존 인증·앱 Shell 테스트 13개 통과. 기존 권한만 사용하는 조회, 탭별 1회 조회, 탭 종료 및 새 선택 후 늦은 응답 무시를 검증했다. 정적 분석도 통과했다.
- 실제 지도 표시·검색·GPS 권한 동작은 위 기기 확인 절차로 별도 검증한다. iOS 빌드는 Windows 개발 환경에서 실행하지 않았다.
