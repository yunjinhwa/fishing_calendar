# 편집 중 기록 변경 보호

출조 기록을 편집하는 동안 다른 기기의 수정·삭제가 이 기기에 반영되면 오래된 입력으로 최신 기록을 덮어쓰지 않는다. 입력은 편집 화면에 유지하고 변경 사실을 안내한다.

## 저장 기준

- 편집 시작 시 표시한 기록과 SQLite의 실제 본문이 같은지 확인한다. 본문·조과·사진과 동기화 메타데이터를 한 트랜잭션에서 읽어 편집 기준을 만든다. 이미 오래된 상세 객체로 편집 화면에 진입한 경우도 거절한다.
- 편집 기준은 기록 ID, 소유 계정, 세션 세대, 본문 스냅샷, optimistic version을 보관한다.
- 저장 트랜잭션에서 현재 본문과 optimistic version을 다시 확인한다. 값이 다르거나 기록이 삭제되었으면 Outbox 추가·버전 예약·로컬 변경 이력·기록 쓰기 전에 거절한다.
- 일반적인 업로드 성공 응답으로 server version만 올라가고 본문과 optimistic version이 그대로인 경우는 편집을 계속할 수 있다.
- 로그아웃 후 같은 계정으로 다시 접속했거나 다른 계정으로 바뀐 경우 이전 편집 기준을 사용할 수 없다.
- 아직 이 기기에 내려받지 않은 서버 변경은 기존 Firestore 기준 버전 검증과 충돌 해결 절차가 보호한다. 저장 전 온라인 조회를 강제하지 않으며 오프라인 편집도 유지한다.

## 화면 동작

- 변경 안내가 표시되어도 입력 필드와 사진 목록을 자동으로 바꾸지 않는다. 저장이 거절되면 같은 화면에 남는다.
- **최신 기록 불러오기**를 누르면 현재 입력이 대체된다는 확인 창이 나온다. **입력 유지**를 선택하면 그대로 남고, **불러오기**를 선택한 경우에만 최신 기록과 편집 기준을 함께 다시 가져온다. 이후 필요한 수정을 다시 입력하여 저장한다.
- 삭제된 기록은 오래된 폼으로 다시 생성하지 않는다. 삭제 안내와 입력은 유지한다.
- 열린 상세 화면은 같은 계정의 저장소 변경을 구독한다. 원격 수정은 즉시 반영하고 삭제되면 삭제 안내와 목록으로 돌아가기 버튼을 표시한다. 수정·삭제 버튼은 비활성화한다.
- 유료 계정의 상세·편집 화면이 열린 동안 해당 기록의 서버 문서 변경을 구독하여 기존 동기화를 실행한다. 상세와 편집은 한 구독을 공유하고, 캐시·미전송 쓰기 이벤트와 이미 반영된 버전은 제외한다. 화면 종료·계정 변경·유료 권한 회수 시 구독을 해제한다.
- 편집→상세, 상세→날짜 목록, 날짜 목록→캘린더로 돌아올 때도 저장 여부와 관계없이 동기화를 요청한다. 진행 중인 서버 조회 사이에 들어온 변경 알림은 후속 조회로 반영한다.
- 상세의 삭제 확인 창도 처음 확인한 기록의 편집 기준을 보관한다. 확인 창이 열린 사이 기록이 바뀌면 삭제를 중단하고 최신 내용을 표시한다.
- 편집 화면과 상세 화면을 닫을 때 저장소·인증 listener를 해제한다.

## 실제 기기 테스트

앱을 완전히 다시 실행한 뒤 같은 유료 계정으로 A/B 두 기기를 로그인하고 기록 하나를 동기화한다. A에서 상세·편집을 열어둔 동안에는 해당 기록의 서버 변경이 동기화된다. 네트워크나 권한 오류가 있으면 연결과 플랜을 확인하고 동기화를 다시 실행한다.

1. **편집 중 수정**: A에서 기록 편집 화면을 열고 위치 또는 메모를 작성한다. B에서 같은 기록의 다른 항목을 수정·동기화한다. A에 최신 변경을 내려받은 뒤 저장한다. 변경 안내가 표시되고 A의 입력이 유지되며, B의 최신 기록이 덮어써지지 않아야 한다.
2. **명시적 다시 불러오기**: 위 상황에서 **최신 기록 불러오기 → 입력 유지**를 선택하면 작성 내용이 남아야 한다. 다시 눌러 **불러오기**를 선택하면 B의 최신 값이 표시되어야 한다. 필요한 항목을 다시 수정·저장하면 B의 다른 변경도 유지되어야 한다.
3. **편집 중 삭제**: A에서 편집 중 B에서 기록을 삭제·동기화한다. A가 변경을 내려받으면 삭제 안내가 표시되어야 한다. A의 저장 시도로 기록이 다시 나타나거나 신규 Outbox가 생기면 안 된다.
4. **상세 실시간 반영**: A의 상세 화면을 열어둔 채 B에서 수정하면 A에 최신 값이 표시되어야 한다. 이어서 B에서 삭제하면 A에는 삭제 안내가 나오고 수정·삭제 버튼이 비활성화되어야 한다.
5. **삭제 확인 중 수정**: A에서 삭제 확인 창을 열어두고 B에서 같은 기록을 수정·동기화한다. A가 최신 변경을 내려받은 뒤 삭제를 확인하면 삭제가 중단되고 최신 기록이 남아야 한다.
6. **오프라인 저장**: A를 오프라인으로 두고 편집·저장한다. B의 변경이 아직 내려오지 않았다면 로컬 저장은 가능하다. 재연결 시 서버 버전이 달라졌다면 기존 충돌 화면에서 해결되어야 한다.

계정 변경과 저장 트랜잭션의 정확한 경계는 자동 회귀 테스트로 검증한다. 실제 기기와 운영 Firebase를 이용한 위 절차는 별도로 확인해야 한다.
