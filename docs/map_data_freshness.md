# 지도 정보 자동 갱신과 만료 표시

브랜치: `fix/map-data-freshness` · 대상: [최초 감사](pre-release-audit.md)의 A-07.

## 갱신 기준

지도 탭이 활성화되어 있고 앱이 화면에 표시되는 동안 다음 갱신 시각을 한 번 예약한다. 일정 간격으로 모든 API를 계속 호출하는 방식은 사용하지 않는다. 탭을 떠나거나 앱이 백그라운드로 이동하면 예약을 취소하고, 복귀 시 현재 정보의 유효기간을 다시 확인한다.

| 정보 | 다시 확인하는 시점 | 표시 기준 |
| --- | --- | --- |
| 날씨·기온 | 조회 후 기본 10분 또는 예보 시간 종료 중 먼저 도래하는 시점 | `validAt`부터 1시간 이내의 예보만 현재 정보로 표시 |
| 현재 수온 | 조회 후 기본 10분 또는 관측 유효기간 종료 중 먼저 도래하는 시점 | 기존 정책대로 선택 위치와 일치하고 관측 후 2시간 이내인 값만 표시 |
| 만조·간조 예보 | 조석 서비스 캐시 만료, 기본 10분 | 선택한 지점·날짜에 해당하는 예보 표시 |
| 오늘의 물때·조석 날짜 | 한국 시간 자정 및 앱 복귀 | 오늘을 따르는 상태에서만 새 날짜로 변경 |

유효기간이 남은 정보는 짧은 앱 복귀나 재연결 때 재사용한다. 앱 복귀만으로 GPS를 다시 요청하거나 검색한 장소를 현재 위치로 바꾸지 않는다. 다른 탭에서 지도 탭에 다시 진입할 때의 기존 현재 위치 처리 흐름은 유지한다.

사용자가 날짜 선택 창에서 고른 조석 날짜는 과거 날짜뿐 아니라 명시적으로 고른 오늘 날짜도 유지한다. 한국 시간 기준 날짜 계산은 기기의 시간대 설정과 분리한다.

## 중복 요청과 실패 처리

- 같은 위치에서 진행 중인 날씨·수온 요청에 복귀·재시도 이벤트가 겹쳐도 추가 요청을 시작하지 않는다.
- 조석은 같은 서비스·지점·날짜의 진행 중 요청을 재사용한다. 대기 중 탭이나 앱이 비활성화되어도 이전 응답이 다른 선택에 반영되지 않도록 세대를 검사한다.
- 날씨·수온은 독립적으로 처리하여 한쪽의 지연·실패가 다른 정보를 막지 않는다.
- 일반 조회 실패 후 자동 재시도는 최소 5분 기다린다. 설정·인증 문제는 자동으로 반복 요청하지 않는다. 사용자의 명시적 재시도와 위치·지점·날짜 변경은 별도로 처리한다.
- 재연결도 기존 정보의 유효기간과 실패 대기 시간을 확인한다. 연결 상태가 일시적으로 `unknown`을 거쳐도 복구를 놓치지 않는다.
- 오프라인에서는 API를 호출하지 않는다. 유효시간을 넘긴 값은 `제공되지 않음`으로 표시한다.

현재 정보 카드 자체에도 API를 호출하지 않는 만료 타이머와 앱 복귀 처리를 적용했다. 지도 상세처럼 부모 화면이 다시 빌드되지 않는 상태에서도 만료된 날씨·수온이 계속 표시되지 않는다. 과거 관측 자료에는 현재 정보의 만료 기준을 적용하지 않는다.

## 검증

다음 테스트에서 실제 API 대신 주입한 서비스와 시계를 사용한다. 시간 경과·자정·백그라운드·재연결·지연 응답을 재현하며, 실제 운영 API 호출이나 휴대전화 시계 변경은 하지 않는다.

- `test/map_data_freshness_test.dart`: 같은 위치의 캐시 만료, 예보 시간 경계, 앱 복귀, 비활성 탭·오프라인, 독립적인 실패 대기, 재연결과 중복 요청·예약 해제.
- `test/tide_panel_freshness_test.dart`: 한국 시간 자정, 수동 날짜 보존, 캐시 만료, 비활성 상태의 응답, 재연결·실패 대기와 예약 해제.
- `test/weather_freshness_test.dart`: 예보 유효기간의 시작·끝과 시간대, 부모 재빌드 없는 만료 표시 및 앱 복귀.
- 기존 지도·수역·조석·수온·과거 조회·기록 자동입력 테스트로 기존 동작을 확인한다.

## 실제 기기 확인

1. 지도에서 현재 위치와 다른 바다 지점을 검색한 뒤 홈 화면으로 나간다. 11분 이상 지난 뒤 복귀했을 때 검색 위치와 지도 상태가 유지되고 날씨·수온·조석 카드가 정상 표시되는지 확인한다. 위치 권한을 다시 묻지 않아야 한다.
2. 앱을 짧게 백그라운드로 보냈다가 여러 번 돌아온다. 정보 카드가 불필요하게 반복 로딩되거나 선택 위치가 바뀌지 않는지 확인한다.
3. 조석 날짜를 과거 날짜로 변경하고 앱 복귀·날씨 재조회·다른 탭 이동 후 복귀를 확인한다. 패널이 유지된 상태에서는 선택 날짜가 오늘로 바뀌지 않아야 한다.
4. 비행기 모드로 전환했다가 해제한다. 연결 복구 후 필요한 정보가 표시되고, 재시도 버튼을 여러 번 눌러도 화면이 멈추거나 이전 위치의 응답이 섞이지 않는지 확인한다.
5. 가능하면 한국 시간 자정 전후로 오늘 날짜의 조석 패널을 유지한다. 자동으로 오늘을 따르는 상태에서는 새 날짜로 바뀌고, 직접 선택한 날짜는 유지되어야 한다. 자정·장기 대기는 자동 테스트에서도 검증한다.

다시 조회해도 제공기관의 실제 값이 같으면 화면의 수치가 바뀌지 않을 수 있다. 데이터가 없는 경우 기존 `제공되지 않음` 표시를 유지한다.

실제 기기의 장기 대기·GPS·네트워크 전환은 직접 실행하지 않았다. DB 마이그레이션, Firebase 규칙 배포와 최종 앱 빌드는 필요하지 않아 실행하지 않았다.
