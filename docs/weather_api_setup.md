# 날씨·기온 API 연동

지도에서 선택한 좌표로 기상청 초단기예보의 현재 시간대 날씨·기온을 조회한다. 초단기예보는 관측값과 구분해 사용하며, 통합 카드에는 날씨·기온과 바다 전용 정보를 표시한다. 출처·격자·발표 기준은 결과 화면에서 생략한다. 데이터가 없으면 `제공되지 않음`으로 표시한다. 물때·만조·간조와 통합 실행 명령은 [조석 API 연결](tide_api_setup.md), 표시 범위는 [바다·민물 판별](water_area_detection.md)을 참고한다.

## 로컬 설정과 실행

현재 사용하는 서비스는 기상청 API허브의 승인된 `getUltraSrtFcst`다. `weather.local.json`을 프로젝트 최상위 폴더에서 열어 다음 두 항목을 설정한다.

```json
{
  "KMA_SERVICE_KEY": "발급받은 인증키",
  "KMA_API_PROVIDER": "apihub"
}
```

`weather.local.json`은 Git에서 제외된다. `weather.example.json`은 키가 비어 있는 공유용 양식이다. 로컬 파일이 없는 환경에서만 예제 파일을 복사한다. 기존 로컬 설정을 복사로 덮어쓰지 않는다.

```powershell
flutter run --dart-define=FIREBASE_AUTH_ENABLED=true --dart-define-from-file=kakao.local.json --dart-define-from-file=weather.local.json
```

Flutter 명령이 PATH에서 인식되지 않는 현재 Windows 환경에서는 다음처럼 실행할 수 있다.

```powershell
& "C:\flutter\bin\flutter.bat" run --dart-define=FIREBASE_AUTH_ENABLED=true --dart-define-from-file=kakao.local.json --dart-define-from-file=weather.local.json
```

설정 파일이나 실행 옵션을 바꾸면 실행 중인 앱을 종료하고 명령을 다시 실행한다. Hot Reload/Restart는 새로운 컴파일 설정을 읽지 않는다. Android Studio의 Additional run args에도 같은 옵션을 넣는다.

인증키의 발급처에 따라 다음 두 설정을 명시적으로 구분한다. 한 키로 두 제공처를 번갈아 시도하지 않는다.

| 발급처 | KMA_API_PROVIDER | 주소·인증 파라미터 |
| --- | --- | --- |
| 기상청 API허브 | `apihub` | `https://apihub.kma.go.kr/api/typ02/openApi/VilageFcstInfoService_2.0/getUltraSrtFcst`, `authKey` |
| 공공데이터포털 | `data_go_kr` | `https://apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getUltraSrtFcst`, `serviceKey` |

공공데이터포털의 인코딩 키는 한 번만 디코딩하며, 디코딩 키의 `+`를 공백으로 바꾸지 않는다. 오류 메시지에는 키나 전체 요청 URL을 표시하지 않는다.

## 조회와 캐시

- 좌표를 기상청 5km 예보 격자로 변환한다. 장소 이름만 직접 입력한 경우에는 지도에서 좌표를 선택하도록 안내하며 API를 호출하지 않는다.
- 현재 KST 시간대의 예보를 포함하는 이전 시각의 `HH30` 발표를 요청한다. 예를 들어 10시대에는 09:30 발표의 10:00 예보를 선택한다. 응답에서 같은 격자·발표·예보 시각의 항목만 결합한다.
- API허브가 요청한 `HH30`을 같은 시각의 `HH00` 기준으로 반환하는 형식을 지원한다. 화면의 발표 기준은 실제 반환된 기준 시각이다. 서로 다른 발표 기준의 항목은 섞지 않는다.
- 강수 형태가 있으면 비·눈 등을 표시하고, 강수 없음이면 하늘 상태 코드를 사용한다. 하늘 상태 없이 강수 없음만 온 경우 맑음으로 추정하지 않는다.
- 기온 결측값(절댓값 900 이상)·비정상 숫자를 비운다. 일부 항목만 있으면 정상 항목을 표시하고 나머지는 수동 입력하도록 안내한다.
- 격자·요청 발표·대상 시간대별로 메모리에 10분 캐시를 보관한다. 앱을 종료하면 캐시는 비워진다. 같은 조회를 동시에 요청하면 네트워크 작업을 공유한다. 캐시는 최대 128개로 제한한다.
- 캐시 만료는 조회 요청 시 확인한다. 시간대가 바뀌면 이전 시간대의 데이터를 재사용하지 않는다. 캐시를 공유하더라도 선택한 장소 이름과 좌표는 각 요청에 맞춰 전달한다.
- 자료 없음에만 이전 발표를 한 번 재조회한다. 인증·호출 제한 오류에는 자동 재시도를 하지 않는다. 각 요청은 12초 제한을 둔다.
- 지도 탭을 떠났거나 위치를 바꾼 뒤 도착한 응답은 해당 화면의 새 데이터를 덮어쓰지 않는다.

## 기록 작성에 전달되는 값

날씨·기온은 출조 시작 시간이 예보의 한 시간 구간에 속하고 장소명·좌표가 일치할 때 자동 입력한다. 시작 시간대나 위치가 달라지면 자동 입력값만 해제한다. 사용자가 직접 수정한 항목, 물때·수온, 기존 기록 수정값은 유지한다.

현재 날씨 예보를 과거 날짜 기록에 자동으로 넣지 않는다. 과거 조회 화면의 가짜 값도 제거했으며, 과거 날씨 조회는 후속 작업이다. 물때는 기록 날짜·좌표를 기준으로 별도 자동 계산하며 수정할 수 있고, 수온은 기록 저장 전 직접 입력해야 한다.

## 실제 기기 테스트

1. 위 명령으로 앱을 실행하고 지도에서 `서울시청` 같은 내륙 위치를 검색한다. 날씨·기온이 표시되고 바다 전용 정보가 숨겨지는지 확인한다.
2. 같은 위치를 다시 검색하고 다른 위치도 선택한다. 이전 위치의 늦은 조회 결과가 새 위치를 덮어쓰지 않아야 한다.
3. 기록 작성으로 이동한다. 해당 시간대 날씨·기온이 채워지고 수온은 빈 상태여야 한다. 해안의 예보 지점을 찾을 수 있으면 물때는 별도로 자동 입력된다. 필요한 항목을 입력한 뒤 저장하고 다시 열어 확인한다. 지도 상세를 거쳐 작성하는 경우도 확인한다.
4. 날씨를 직접 고친 다음 시작 날짜를 과거로 변경한다. 직접 고친 날씨는 유지되고 자동으로 채웠던 기온은 비워져야 한다.
5. 날씨·기온을 자동 입력한 상태에서 장소명이나 좌표를 변경한다. 이전 위치의 자동 입력값은 비워져야 한다.
6. 인터넷을 끄거나 좌표 없는 장소를 직접 입력한다. 조회 불가 안내가 나오고 기록에서는 값을 직접 입력해 저장할 수 있어야 한다.
7. 과거 정보 조회 화면에는 임의의 날씨·물때·수온 값이 표시되지 않아야 한다.

Android 실제 화면 조작은 사용자가 확인한다. 개발 중 별도로 실제 인증키를 사용한 읽기 요청으로 API허브의 정상 응답과 날씨·기온 수신을 검증한다.

## 개발 검증 기록 (2026-11-02)

- 전체 Flutter 테스트 530개 통과
- `flutter analyze --no-pub` 오류 없음
- 두 로컬 설정 파일을 사용한 Android debug APK 빌드 성공
- API허브 실제 키로 서울 예보 격자 `(60, 127)`의 날씨·기온·기준 및 예보 시각 수신 확인
- 실제 키가 Git 커밋 후보 파일에 포함되지 않음을 확인
- 실제 Android 화면의 최종 동작은 위 절차로 확인한다. iOS 빌드·실기기 검증은 진행하지 않았다.
