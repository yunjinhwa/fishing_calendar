# 앱 시작 시 DB 오류 복구

브랜치: `fix/startup-database-recovery` · 대상: [최초 감사](pre-release-audit.md)의 A-04.

## 수정한 문제

기존에는 DB와 기록·계정 초기화를 모두 기다린 뒤 `runApp`을 호출했다. SQLite 열기나 업그레이드에 실패하면 앱 화면이 뜨지 않아 오류 안내와 재시도를 할 수 없었다.

이제 첫 화면을 먼저 표시하고, 필요한 준비가 끝난 뒤 기존 앱을 연다. 실패하면 해당 단계의 안내와 **다시 시도** 버튼을 표시한다. 복구를 위해 DB를 삭제하거나 기록·사진을 초기화하지 않는다.

정상 준비 화면은 앱 아이콘·이름과 작은 로딩 표시만 사용한다. ‘기록을 불러오고 있습니다’ 같은 단계별 문구를 표시하지 않으며, 최소 노출 시간을 강제하지 않는다. 단계가 바뀔 때마다 같은 시작 화면을 다시 만들지 않는다.

## 초기화 순서와 재시도

| 순서 | 처리 | 실패 시 동작 |
| --- | --- | --- |
| 1 | SQLite 열기·스키마 업그레이드 | 인증을 시작하지 않고 복구 화면 표시 |
| 2 | Firebase·동기화 게이트웨이 연결 | 해당 단계 재시도 |
| 3 | 기존 탈퇴 정리 재개 → 계정 세션 복원 | 완료한 단계는 유지하고 실패한 단계 재시도 |
| 4 | 기록·Outbox·충돌 로드 → 기록 복구 → 요금제 이전 재개 | 로컬 준비 묶음을 다시 로드·검증 |
| 5 | 캐시·동기화·사진 정리 서비스 시작 | 완료한 등록은 반복하지 않음. 사진 정리 오류는 로그를 남기고 앱 진입 허용 |

진행 중 재시도 요청은 같은 작업을 공유한다. 성공한 인증 연결·세션 복원은 이후 기록 읽기가 실패했다고 다시 실행하지 않는다. 로컬 준비 중 세션이 바뀌면 중단하고 재시도에서 현재 계정 데이터를 읽는다. 복구 화면이 열린 동안 계정이 바뀌었다면 작업자 시작 전에 계정별 캐시를 다시 확인한다.

계정 탈퇴 정리는 세션 복원보다 앞에 유지한다. 사용자가 이미 요청한 탈퇴의 정리와 세션 무효화 장벽을 선택 작업으로 옮기지 않는다. 파일 정리가 실패하면 기존 서비스가 보관하는 재시도 표식도 유지한다.

네트워크 감지 오류와 자동 사진 정리 실패는 기록 저장소의 준비 실패와 분리한다. 정상 앱과 생명주기 리스너는 필수 단계가 끝난 뒤 생성하고, 최초 명시적 동기화 요청은 정상 앱의 첫 프레임 이후에 실행한다. 진행 중 화면이 제거되면 늦은 완료 알림으로 화면을 갱신하거나 다음 시작 단계를 실행하지 않는다. 이미 진행 중인 DB 작업을 강제로 취소하지는 않는다.

## 시작 대기 줄이기

| 변경 | 검증한 효과와 조건 |
| --- | --- |
| 요금제·닉네임 조회 병렬화 | 탈퇴 확인과 로컬 계정 이전 뒤에 두 조회를 함께 시작한다. 한쪽이 실패해도 다른 쪽이 끝날 때까지 인증 잠금을 유지하고, 결과 적용 전 UID를 다시 검사한다. |
| Auth 표시명 갱신 제외 | 세션 복원은 검증된 Firestore 닉네임을 바로 사용한다. UI와 무관한 Auth 표시명 미러 갱신은 직접 로그인·가입 시 처리한다. |
| 변경 없는 복구 후 재조회 생략 | 정상 유료 시작에서 이미 읽은 기록·조과·사진·Outbox의 후속 SELECT 4회를 줄인다. 트랜잭션의 최신 읽기, 변경이 있는 경우와 아직 캐시를 읽지 않은 계정의 조회는 유지한다. |
| 완료한 레거시 이전 확인 재사용 | 같은 열린 DB에서 두 이전과 원본 preferences 정리가 성공한 경우만 메타데이터 재조회를 생략한다. 손상 데이터·SQL/백업/정리 실패·새 레거시 원본·DB 재오픈/교체에서는 다시 확인한다. |

탈퇴 확인·서버 요금제 검증을 생략하거나 확인 전 화면에 진입시키지 않는다. 디버그 로그의 `AppStartupTiming`에서 각 단계의 밀리초를 확인할 수 있다. 실제 기기의 시작 시간이 몇 초 줄었는지는 측정하지 않았으며 네트워크·보관 기록량에 따라 달라진다.

## DB 오류와 인증 오류 구분

Firebase 세션 복원 내부에서도 기존 계정의 로컬 데이터 이전을 위해 SQLite를 사용한다. 따라서 DB 열기·업그레이드를 인증보다 먼저 확인한다.

DB가 열린 뒤의 계정 데이터 이전에서 `DatabaseException`이 발생하는 경우도 별도로 처리한다. 이를 비밀번호 오류로 바꾸거나 네이티브 계정을 로그아웃하지 않고 시작 화면으로 전달하여 재시도할 수 있게 한다. 일반 인증 실패의 기존 처리는 유지한다.

원본 DB 열기 Future의 실패 해제와 업그레이드 트랜잭션 롤백은 기존 저장소 동작을 사용한다. DB 버전·테이블·Firestore 규칙을 변경하지 않으며 별도 마이그레이션·배포는 필요하지 않다.

업그레이드 중 실제 SQL 오류를 주입했으며 실패 후 파일의 스키마·행·버전·무결성과 재시도를 확인했다. 실제 저장 공간 부족이나 손상된 기기 디스크를 재현한 것은 아니다. 최종 앱 빌드·배포 및 실제 기기 검증은 실행하지 않았다.

## 실제 기기 확인

1. **재실행과 데이터 보존:** 무료·유료 테스트 계정으로 앱을 완전히 종료한 뒤 다시 연다. 앱 이름 중심의 시작 화면 뒤 기존 화면으로 진입하고 계정·기록·같은 기기의 사진이 유지되는지 확인한다. ‘기록을 불러오는 중’ 같은 단계별 문구는 표시되지 않는다. 빠른 기기에서는 시작 화면이 짧게 지나갈 수 있다.
2. **오프라인 시작:** 인터넷을 끈 상태로 재실행하여 기기에 저장된 기록을 확인한다. 다시 연결했을 때 기존 요금제 권한에 따라 동기화되는지 확인한다.
3. **미전송 요청:** 유료 테스트 계정에서 오프라인으로 기록을 수정한 뒤 앱을 종료·재실행한다. 온라인 복귀 후 수정이 한 번 반영되고 Outbox가 완료되는지 확인한다.

오류 안내·연속 재시도·업그레이드 실패는 자동 주입 테스트로 확인했다. 실제 기기에서 확인하기 위해 DB 파일이나 앱 데이터를 지우거나 손상시킬 필요는 없다.
