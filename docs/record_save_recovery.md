# 기록 저장 실패와 작성 취소 처리

`fix/record-save-recovery`는 작성 중 입력을 실수로 버리는 상황과 저장·삭제 실패 후 재시도를 보완한다.

## 화면 동작

- 작성·수정 화면에서 텍스트, 시간, 장르, 조과, 사진 목록이 처음 표시한 값과 달라졌을 때 뒤로가면 폐기 확인 창을 표시한다. 상단 뒤로가기와 시스템 뒤로가기에 같은 정책을 적용한다.
- **계속 작성**은 입력을 유지하고, **나가기**는 저장하지 않고 화면을 닫는다. 변경하지 않았거나 모든 값을 원래대로 되돌렸으면 확인 없이 돌아간다.
- 지도·도감에서 전달한 초기 값과 기존 기록은 최초 기준으로 취급한다. **최신 기록 불러오기**를 확인하고 새 값을 불러온 경우에는 그 값으로 기준을 갱신한다.
- 저장 중에는 입력과 추가 저장을 막고 화면을 유지한다. 삭제는 최초 클릭부터 중복 진입을 막고 실제 삭제 중 뒤로가기를 제한한다. 성공하면 기존과 같이 호출 화면에 `true`를 반환한다.
- 로컬 저장·삭제가 실패하면 화면과 입력 또는 기존 기록을 유지하고 오류를 안내한다. 작업 잠금을 해제하여 다시 저장·삭제할 수 있게 한다.
- 유료 회원의 오프라인 로컬 저장 성공과 Outbox 대기는 정상 상태다. 서버 전송 실패를 로컬 저장 실패로 안내하지 않는다.

## 저장 확정 경계

기록, 조과·사진 행, Outbox, 버전, 무료 변경 이력은 기존과 같이 SQLite 트랜잭션으로 변경한다. 화면 갱신에 필요한 기록·Outbox 조회와 디코딩도 같은 트랜잭션 안에서 완료한다. 조회까지 성공해야 커밋하므로 커밋 후 재조회만 실패하여 사용자에게 중복 저장을 유도하는 경계를 없앤다.

커밋 성공 직후 명시한 소유 계정의 Outbox 캐시부터 반영하고 기록 캐시를 반영·알림한다. 이 단계에서는 DB 작업이나 비동기 대기를 하지 않는다. 실패 시에는 DB와 두 캐시 모두 기존 상태를 유지한다.

## 실제 기기 확인

앱을 다시 실행한 뒤 무료 또는 유료 회원으로 확인한다.

1. 새 작성 화면에 들어가 아무것도 바꾸지 않고 뒤로간다. 확인 창 없이 돌아가야 한다. 기존 기록 수정 화면도 동일하다.
2. 위치 또는 메모를 입력하고 뒤로간다. **계속 작성**을 누르면 입력이 남아야 한다. 다시 뒤로가서 **나가기**를 누르면 기록이 생성·수정되지 않아야 한다. 상단 버튼과 시스템 뒤로가기를 각각 확인한다.
3. 기존 기록의 위치를 바꿨다가 원래 값으로 되돌리고 뒤로간다. 다른 변경이 없으면 확인 창이 없어야 한다. 시간·장르·조과·사진 제거만 바꾼 경우에는 확인 창이 있어야 한다.
4. 정상 저장 후 목록·상세의 값이 맞는지 확인한다. 저장 버튼을 빠르게 여러 번 눌러도 기록이 하나만 생겨야 한다. 유료 회원은 오프라인 저장 후 연결을 복구하여 정상 동기화되는지 확인한다.
5. 삭제 확인에서 **취소**를 누르면 기록이 남고, 다시 **삭제**하면 기록이 한 번만 삭제되어야 한다. 기존 다른 기기의 수정·삭제 반영과 충돌 해결도 유지되어야 한다.

디스크·DB 오류와 진행 중 작업의 정확한 경계는 아래 자동 테스트에서 실패와 지연을 주입하여 검증한다. 실제 기기 저장공간을 고의로 가득 채울 필요는 없다.
