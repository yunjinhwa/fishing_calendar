# 조석 예보 API 연동

국립해양조사원의 일별 고조·저조 예보를 지도와 기록 작성 화면의 참고 정보로 표시한다. 지도는 날씨·기온과 바다의 물때·수온·만조·간조를 한 카드로 보여 준다. 만조·간조 시각과 예측 조위(cm)는 예보 지점의 값이다. 물때 명칭은 한국 음력 날짜와 지역별 기준으로 계산한다. [수온 API](water_temperature_api_setup.md)는 주변 관측소의 최신 실측값을 별도로 조회하고 없으면 `제공되지 않음`으로 표시한다.

## 설정과 실행

[국립해양조사원 조석예보(고, 저조)](https://www.data.go.kr/data/15156018/openapi.do)에 활용 신청하고 공공데이터포털 인증키를 발급받는다. 프로젝트 최상위 `tide.local.json`에 설정한다.

```json
{
  "KHOA_SERVICE_KEY": "발급받은 인증키"
}
```

`tide.local.json`은 Git에서 제외된다. `tide.example.json`은 키가 없는 공유용 양식으로 유지한다. 기상청 API허브 키와 별도이며, 인코딩 키는 한 번만 디코딩하고 `+` 문자를 보존한다.

기존 실행을 종료하고 세 로컬 설정을 포함해 다시 실행한다. Hot Reload/Restart만으로 새 컴파일 설정을 읽지 않는다.

```powershell
& "C:\flutter\bin\flutter.bat" run --dart-define=FIREBASE_AUTH_ENABLED=true --dart-define-from-file=kakao.local.json --dart-define-from-file=weather.local.json --dart-define-from-file=tide.local.json
```

Android Studio의 Additional run args에도 같은 옵션을 넣는다.

## 조회 방식

- 주소: `https://apis.data.go.kr/1192136/tideFcstHghLw/GetTideFcstHghLwApiService`
- 요청: `serviceKey`, `obsCode`, `reqDate=YYYYMMDD`, `type=json`, `pageNo`, `numOfRows=300`
- 응답: `header`·`body.items.item`의 예보 지점명·위경도·예측일시·예측조위·극치구분을 사용한다.
- 극치구분 `1/3`은 만조, `2/4`는 간조다. 오전·오후별 값이 모두 있거나 하루 네 건이라는 가정은 하지 않는다.
- KST 예측 시각을 UTC로 보관하고 화면에는 KST로 표시한다. 요청 날짜와 다른 날짜의 값이나 서로 다른 지점의 항목이 섞인 응답은 사용하지 않는다.
- 조위는 cm로 표시하며 유한한 음수도 허용한다. 시간순으로 정렬하고 정확히 같은 중복 항목을 제거한다.
- 예보 지점·날짜별로 메모리에 10분 캐시를 보관한다. 같은 조회의 동시 요청을 공유하고 캐시는 최대 128개로 제한한다.
- 한 요청은 12초로 제한한다. 인증·호출 제한 오류에 자동 재시도하지 않는다. 페이지 정보가 있으면 최대 4페이지 범위에서 누락 없이 수집하며 불완전한 결과를 정상 결과로 표시하지 않는다.
- 날씨와 조석은 각각 조회한다. 한쪽 조회 실패가 다른 쪽 표시나 기록 작성을 막지 않는다.

## 물때 명칭 자동 계산

물때 명칭은 조석 API가 제공하는 값이 아니다. 한국 음력 날짜를 기기 안에서 변환하고 [물때표 기준](https://www.badatime.com/guide)에 따라 계산한다. 날짜·지역별 관습 명칭이며 조위나 유속을 계산하는 기능과 구분한다.

- 지도에서 바다로 판별하거나 직접 바다를 선택한 경우 KST 날짜와 예보 지점에 따라 물때 명칭을 표시한다. 음력 날짜·7물때식/8물때식은 계산에 사용하며 지도 카드에는 표시하지 않는다. 바다 여부가 확인되면 물때 계산 자체에는 인터넷 연결이 필요하지 않다.
- 84개 지점의 기준을 코드별로 명시한다. 서해는 7물때식, 남해·동해·제주·추자·이어도와 완도는 8물때식을 기본으로 하며, 남서해 섬은 경도만으로 분류하지 않는다. 바다타임의 일반적인 지역 구분을 따른 기본값이며 모든 지역의 관습이 동일한 것은 아니다.
- 예를 들어 양력 2026-11-02(음력 9.23)는 양쪽 모두 `조금`, 2026-11-03(음력 9.24)은 7물때식 `무시`, 8물때식 `1물`이다. 29일인 음력 달은 30일 항목을 생략하고, 윤달도 같은 음력 일자표를 적용한다.
- 양력 2020-01-01~2035-12-31을 지원한다. 범위 밖 날짜나 기준이 없는 지점은 지도에 `제공되지 않음`으로 표시한다. 한국 음력은 일부 날짜에서 중국 음력과 달라 한국 달력 자료를 사용한다.
- 한국 달력 자료는 MIT 라이선스의 `klc 0.1.0`에서 필요한 연도만 가져왔다. 원 패키지는 Dart 3을 지원하지 않아 의존성을 추가하지 않고 작은 오프라인 변환기로 구현했다. [원본](https://pub.dev/packages/klc/versions/0.1.0), [라이선스](../third_party/klc_LICENSE.txt)를 보존하고 앱 라이선스 목록에도 등록한다.
- 변환 검증 기준: [한국천문연구원 월별 음양력](https://astro.kasi.re.kr/life/pageView/5), [2023년 윤달](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2023), [2027년 한국 설날](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2027).

## 예보 지점 목록

공식 조석 API 활용가이드의 예보 지점 코드 166개와 공식 타이드베드 기준항 조화상수 CSV의 지점 코드·위경도를 대조했다. 두 자료의 코드가 같은 77개 지점과, 이름이 일치하고 현행 API로 코드·좌표를 확인한 7개 지점을 `lib/data/tides/khoa_tide_stations.dart`에 포함한다. 총 84개이며, 현행 지점과 대응을 확인하지 못한 순위도·원산·녹동은 제외했다.

CSV의 과거 코드만으로 대조하면 가덕도 등이 빠지고 인근의 다른 예보 지점이 기본 선택될 수 있다. 다음 7개는 2026-11-02 예보 API의 반환 지점명과 좌표를 확인해 현행 코드를 사용한다. 과거 CSV 좌표와 현행 좌표가 다른 지점도 있어 이름만 바꾸거나 과거 좌표를 그대로 사용하지 않는다.

| 예보 지점 | CSV의 과거 코드 | 현행 예보 코드 |
| --- | --- | --- |
| 가덕도 | `DT_0019` | `DT_0063` |
| 독도 | `DT_0040` | `DT_0903` |
| 마산 | `DT_0015` | `DT_0062` |

바다로 확인된 선택 위치에서 직선거리 50km 이내인 지점 중 가까운 순으로 최대 5개를 제시한다. 동일 거리에서는 코드순으로 정렬한다. 첫 지점을 기본 선택하고 목록에서 다른 주변 지점을 선택할 수 있다. 실제 조회 지점은 선택 항목으로 표시하며 직선거리는 화면에서 생략한다. 민물·내륙이나 판별되지 않은 위치에서는 지점 검색과 조석 API 호출을 하지 않는다. [바다·민물 자동 판별](water_area_detection.md)을 참고한다.

API가 반환한 지점 좌표가 목록의 좌표에서 1km 넘게 벗어나면 잘못된 지점 응답으로 처리한다. 목록 갱신 시에는 아래 두 공식 자료를 다시 대조해 코드·좌표를 함께 확인한다.

## 화면과 기록 작성

지도는 `날씨·낚시 정보` 한 카드에 날씨·기온과 바다 전용 정보를 구분해 표시한다. 바다에서는 예보 지점·날짜를 선택하고 물때·수온·만조·간조 시각·조위를 확인한다. 민물·내륙과 판별 불가 위치에서는 바다 전용 항목을 숨긴다. 날짜·지점을 바꾸면 물때와 예보가 함께 갱신되며, 만조·간조 API 오류에도 계산 가능한 물때는 유지한다. 값이 없으면 `제공되지 않음`을 표시한다. 화면에서 출처·격자·발표 기준·거리·음력·계산 기준과 수동 입력 안내는 제거했다.

지도에서 조회한 조석은 지도 상세와 기록 작성 화면에도 참고용으로 전달한다. 기록 시작일의 KST 날짜와 장소명·좌표가 일치할 때만 참고 예보를 보여 준다. 날짜·장소가 달라지면 해당 참고 표시를 숨기고, 사용자가 입력한 물때·수온은 유지한다. 만조·간조 요약을 물때 명칭 입력란에 자동 저장하지 않는다.

새 기록의 물때 입력란은 출조 시작일의 KST 날짜와 좌표를 기준으로 계산한 명칭을 채운다. 지도에서 민물·판별 불가 위치로 진입한 기록은 자동 물때와 조석 참고 정보 전달을 차단한다. 바다의 같은 장소 선택 지점이 있으면 그 기준을 유지하며, 그 외에는 가까운 예보 지점을 찾는다. 날짜·좌표가 바뀌면 자동 입력값을 갱신하고, 자동 계산이 불가능해지면 자동 입력값만 비운다. 직접 입력·수정·비우기, 명시적으로 전달한 초기 물때, 기존 기록 수정값은 보존한다. 입력 변화가 없으면 같은 계산을 반복하지 않는다.

탭을 떠나거나 지점·날짜·장소를 바꾸면 이전 응답을 무효화한다. 활성 지도에서 스크롤로 조석 영역이 화면 밖에 나가도 조회 상태와 선택값을 유지한다. 날짜를 직접 선택하지 않았다면 탭 재진입 시 바뀐 KST 날짜를 따른다.

## 실제 기기 확인

1. 위 명령으로 실행하고 바다 위치와 흰여울문화마을 같은 해안 지점을 선택한다. 자동 판별 결과와 통합 카드의 날씨·기온·물때, 만조·간조 시각·cm 단위 조위를 확인한다. 바다 경계에서 500m 이내인 육지는 자동으로 바다 정보를 제공하며, 판별 결과는 `바다 / 민물`로 직접 변경할 수 있다.
2. 후보가 둘 이상인 위치에서 다른 예보 지점을 선택한다. 표와 지점명이 선택한 지점에 맞게 바뀌어야 한다.
3. 날짜를 어제나 내일로 바꾼다. 지원되는 날짜는 해당 날짜의 예보가 나오고, 자료가 없으면 안내가 나와야 한다.
4. 지점·날짜·장소를 빠르게 바꾼다. 마지막 선택과 다른 이전 응답이 표시되지 않아야 한다.
5. 바다의 현재 날짜로 조회한 뒤 기록 작성으로 이동한다. 같은 날짜·장소의 조석 참고 정보와 자동 계산한 물때가 표시되고, 수온은 관측 시각·장소 조건이 맞을 때만 자동 입력되어야 한다. 수온 조회에 실패하면 빈 상태로 직접 입력할 수 있다. 지도 상세를 거치는 경우도 확인한다.
6. 기록에 물때·수온을 직접 입력한 뒤 시작 날짜나 장소를 바꾼다. 이전 참고 예보는 숨겨지고 직접 입력한 값은 유지되어야 한다. 필수 항목을 채워 저장한 뒤 물때 명칭이 그대로 보존되는지 확인한다.
7. 인터넷을 끄거나 좌표 없는 장소를 직접 입력한다. 조석 조회 불가 안내가 나오고 기록을 직접 작성할 수 있어야 한다. 연결 복구 후 활성 지도에서 다시 조회되어야 한다.
8. 다른 탭에 머무르는 동안 새 조석 조회가 발생하지 않고, 지도 복귀 후 정상 표시되는지 확인한다.
9. 가덕도 조위관측소 인근을 선택하고 예보 지점이 `가덕도`인지 확인한다. 2026-11-02의 만조 `02:15·127cm`, 간조 `07:54·76cm`, 만조 `14:48·152cm`, 간조 `21:09·80cm`를 [스마트 조석예보](https://www.khoa.go.kr/swtc/mobile.do)의 가덕도 만·간조 표시와 대조한다. 선택한 위치가 다르면 기본 예보 지점도 달라질 수 있으므로 지도 장소명과 예보 지점명을 구분한다.
10. 바다로 선택한 지도의 날짜를 2026-11-03으로 선택한다. 인천·군산은 `무시`, 가덕도·부산은 `1물`이 표시되어야 한다. 인터넷을 꺼도 해당 위치의 물때 명칭은 유지되고 조회되지 않는 값은 `제공되지 않음`으로 표시한다.
11. 새 기록에서 물때를 직접 수정하기 전 시작 날짜를 변경하면 자동 명칭이 갱신되어야 한다. 직접 수정하거나 비운 다음에는 날짜·좌표를 바꿔도 해당 입력을 덮어쓰지 않아야 한다. 저장 후 다시 열어 값이 유지되는지도 확인한다.
12. 한강·시화호를 선택해 민물·내륙 자동 판별과 바다 정보 숨김을 확인한다. 바다를 조회하는 중 민물로 바꿔도 이전 만조·간조나 물때가 다시 나타나면 안 된다. 지도 상세에서도 같은 제한을 적용한다.

Android 화면 조작은 사용자가 확인한다. iOS 빌드·실기기 검증은 별도로 진행한다.
