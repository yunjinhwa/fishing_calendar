# 유료 기록 캐시 정책

유료 회원의 서버 원본은 보존하고, 기기의 평상시 기록 본문은 최근 31일로 관리한다. 과거 캘린더와 기록 검색·내 기록어는 화면을 열 때 서버에서 보완한다. 무료 회원의 로컬 원본에는 이 정리를 적용하지 않는다.

## 보관 기준

- 기기 현지 날짜의 오늘과 이전 30일에 겹치는 기록을 보관한다. 예를 들어 2026년 10월 26일이면 9월 26일 00:00 이후까지 이어지는 기록을 보관한다. 그 시각에 정확히 끝난 기록은 과거 기록이다.
- 진행 중인 기록과 미래 기록은 보관한다. 시작일이 오래되었어도 종료 시각이 보관 범위에 걸치면 유지한다.
- 현재 보고 있는 캘린더 월, 열린 상세·수정 화면의 기록은 임시로 보관한다. 검색·내 기록어 화면을 보고 있는 동안에는 전체 이력을 임시로 보관한다. 해당 화면이나 탭을 벗어나면 다시 정리할 수 있다.
- 미완료 Outbox, 미해결 충돌, 무료 기간 변경 이력, 서버 확정 전 버전은 정리하지 않는다. 요금제 이전이 끝나지 않았거나 서버 버전이 확인되지 않은 기록도 보호한다.
- 정리는 앱 시작·기록 변경·동기화 완료·화면 보관 범위 변경 때 수행한다. 앱 종료 중 실행하는 예약 작업은 아니다.

본문 정리는 사용자 삭제와 다르다. 서버 삭제 요청이나 Outbox를 만들지 않으며, 서버 버전과 증분 동기화 체크포인트를 유지한다. 평소 동기화에서 과거 기록을 받아도 버전과 진행 위치만 갱신하고 불필요한 본문 복원을 생략한다.

## 과거 기록 조회

캘린더에서 보관 범위 이전의 날짜가 포함된 월을 열면 해당 월과 겹치는 기록을 서버에서 최대 100개씩 조회한다. 다른 월에서 시작한 장기 출조와 월말을 넘긴 기록도 포함한다. 조회는 `startAt < 다음 달 시작`, `endAt > 해당 달 시작` 조건과 정밀 timestamp·문서 ID 커서를 사용한다.

기록 검색과 내 기록어는 전체 이력 기준을 유지하기 위해 화면 진입 시 서버 전체 이력을 한 번 읽는다. 같은 화면을 보고 있는 동안 반복 로드는 공유하며, 필터 입력·정렬 변경마다 서버를 조회하지 않는다. 전체 이력 조회는 기록 수에 비례한 읽기가 발생한다.

오프라인에서는 현재 기기에 있는 기록을 표시하고 안내한다. 아직 내려받지 않은 과거 기록까지 표시할 수는 없다. 연결 복구 시 다시 조회하고, 조회 오류에는 재시도 버튼을 제공한다. 일부 페이지를 받은 뒤 실패해도 이미 받은 기록은 유지한다.

완료한 조회에서 빠진 기존 본문은 조회 시작 시 버전과 현재 버전이 같은 경우에만 정리한다. 조회 도중 추가·변경된 기록과 미완료 로컬 변경은 보호한다. 월 조회는 전역 증분 체크포인트를 전진시키지 않는다. 조회 도중 다른 기기에서 기간이 바뀌면 페이지 순서가 달라질 수 있으며, 해당 월 재진입으로 다시 확인할 수 있다.

## 사진과 계정

사진 파일은 계속 기기에만 저장한다. SQLite v5의 독립 사진 아카이브에 참조를 보관하므로 본문을 정리해도 파일이 함께 삭제되지 않는다. 같은 기기에서 과거 기록을 다시 읽으면 사진을 복원한다. 다른 기기에 사진을 전송하는 기능은 없다.

사진 제거·실제 기록 삭제·계정 데이터 삭제에서는 아카이브도 정리한다. 계정 소유권 이전에는 본문 없이 사진 참조만 남은 기록도 포함하고, 다른 계정의 동일 ID와 충돌하면 이전을 중단한다. 기존 SQLite v4 사진 참조는 자동 이전하며 별도 SQL 설치는 필요 없다.

사용자가 선택한 무료 전환 정책은 다음과 같다.

- 전환 시 기기에 이미 내려받은 기록을 유지한다. 무료 상태에서는 31일 정리를 하지 않는다.
- 서버에만 남은 과거 기록은 보존한다. 무료 전환 직전에 서버 전체 기록을 추가 다운로드하지 않는다.
- 무료 상태에서는 서버 과거 기록을 조회하지 않는다. 다시 유료가 되면 조회할 수 있다.
- 무료 기간에 수정·삭제한 기록은 기존 변경 이력과 재승급 이전 절차로 처리한다.

## Firebase 설정

추가한 월 조회 복합 인덱스는 `recordStatus ASC`, `endAt ASC`, `startAt ASC` 순서다. 프로젝트 루트에서 사용자가 배포한다.

```powershell
firebase deploy --only 'firestore:indexes' --project fishingbuild
```

Firebase Console의 Firestore 인덱스가 준비된 뒤 과거 월 조회를 확인한다. 인덱스 생성 중이거나 누락되면 조회 오류와 재시도 안내가 나올 수 있다. 이 작업에서 운영 배포는 실행하지 않았으며, 보안 규칙 변경은 없다.

조회 계약: [Firestore 다중 필드 범위 조건](https://firebase.google.com/docs/firestore/query-data/multiple-range-fields), [쿼리 커서](https://firebase.google.com/docs/firestore/query-data/query-cursors).

## 실제 기기 테스트

서버에 최근 기록과 31일보다 오래된 기록을 함께 준비한다. 사진 보존 확인용 과거 기록은 현재 기기에서 사진을 첨부한 기록을 사용한다.

1. **최근·과거 표시:** 유료 계정으로 재실행·동기화한다. 최근 기록, 오늘까지 이어지는 장기 출조, 미래 기록이 표시되는지 확인한다. 과거 월을 열면 과거 기록과 월 경계를 넘는 출조가 표시되어야 한다. 다른 탭에 갔다가 같은 월을 다시 열어도 복원되어야 한다.
2. **사진:** 과거 기록이 있는 월에서 다른 탭으로 이동한 뒤 돌아와 다시 조회한다. 같은 기기의 첨부 사진이 유지되고 서버 원본이 삭제되지 않아야 한다.
3. **오프라인·재시도:** 비행기 모드에서 아직 조회하지 않은 과거 월을 연다. 안내가 표시되고 화면이 계속 깜빡이거나 로딩을 반복하지 않아야 한다. 연결을 복구하면 기록을 조회한다. 조회 오류가 발생하면 재시도로 복원되는지 확인한다.
4. **미전송·충돌:** 오프라인으로 과거 기록을 수정하거나 충돌을 만든다. 월 이동과 탭 전환 후에도 내 변경·첨부 사진·대기열이 유지되어야 한다. 연결 복구 후 기존 동기화·충돌 해결이 정상이어야 한다.
5. **검색·내 기록어:** 기록 탭에서 오래된 장소·어종·메모를 검색하고 기간 필터를 적용한다. 내 기록어에서 오래된 최대어도 표시되어야 한다. 오프라인에서는 기기에 남은 기록 기준이라는 안내가 보여야 한다.
6. **무료 전환·재승급:** 과거 월을 열어 기록을 내려받은 상태에서 무료로 바꾼다. 기기의 기록은 재실행 후에도 유지되어야 하고, 서버에만 있는 과거 기록은 무료에서 새로 조회되지 않아야 한다. 무료 기간의 수정·삭제를 만든 뒤 다시 유료로 바꾸면 기존 이전 정책대로 반영되고 다른 서버 과거 기록은 보존되어야 한다.
7. **계정 전환:** 과거 조회 중 로그아웃하거나 다른 계정으로 바꾼다. 이전 응답·사진·기록이 새 계정에 표시되지 않아야 한다.

## 자동 검증

2026-10-26 기준 전체 테스트 **394개 통과**, `flutter analyze --no-pub` 문제 없음. 실제 SQLite를 이용한 저장·이전·축출·복원·체크포인트·경쟁 상황 검증과 화면 테스트를 포함한다. 로컬 데모 프로젝트의 Firebase Auth·Firestore 에뮬레이터에서 기간 쿼리, 페이지 경계, 월 겹침, 삭제 제외, 다른 계정 접근 제한 스모크 테스트를 통과했다. 실제 기기 및 운영 인덱스 준비 상태는 별도 확인이 필요하다.

```powershell
flutter test --no-pub --concurrency=1
flutter analyze --no-pub
firebase emulators:exec --only 'auth,firestore' --project demo-fishing-paid-cache 'node tool/firestore_rules_smoke.mjs'
```
