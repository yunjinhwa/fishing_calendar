# 요금제 전환 중 기록 보존

유료에서 무료로 전환한 동안 수정·삭제한 기록은 기기를 원본으로 취급한다. 다시 유료로 전환하면 기존 전송 요청을 먼저 복구하고 최신 수정·삭제를 후속 요청으로 반영한다.

## 처리 원칙

- 무료 기간의 변경은 기록 저장/삭제와 같은 SQLite 트랜잭션에서 `local_record_changes`에 기록한다. 기록을 삭제해도 삭제 의도는 남는다. 무료 상태에서는 이 이력을 서버에 전송하지 않는다.
- 유료 재전환 시 기존 Outbox 요청의 ID·본문·작업 종류·기준 버전을 바꾸지 않는다. 서버 반영 후 응답을 잃어도 동일 요청을 재시도하여 원래 영수증을 복구한다. 최신 변경은 새로운 ID와 후속 버전으로 추가한다.
- 이전 앱에서 이미 같은 요청 ID의 본문이 바뀌어 `idempotency-conflict`가 발생한 경우는 최신 서버 기록과의 충돌로 표시한다. 사용자가 변경을 선택하면 새 요청으로 해결할 수 있다. 지문만으로 알 수 없는 원래 본문을 추측하여 자동 승인하지 않는다.
- 무료 기간 삭제도 유료 재전환 시 서버 삭제로 반영한다. 서버에 올라간 이력이 없는 무료 기록을 생성 후 삭제한 경우는 서버 요청 없이 정리한다.
- 앱 시작 시 마이그레이션 대기 또는 무료 변경 이력이 있으면 오래된 일반 Outbox 내용을 로컬 기록 위에 재생하지 않는다. 동기화도 서버 조회·전송 전에 마이그레이션을 준비한다.
- 마이그레이션은 시작 시 UID·owner key·세션 세대를 고정한다. 모든 SQL 작업은 그 owner에 한정하며, 계정 변경이나 권한 회수가 확인되면 트랜잭션을 롤백한다. 로그아웃 후 같은 계정에 재접속한 경우도 이전 작업으로 이어지지 않는다.
- 같은 세션의 동시 재개 요청은 하나의 작업을 공유한다. 기록·Outbox·변경 이력은 같은 트랜잭션에서 읽고, 후속 요청 생성과 변경 이력 소비도 함께 커밋한다.
- 다른 기기의 최신 변경과 버전이 충돌하면 기존 충돌 해결 화면에서 선택한다. 이미 미해결 충돌이 있던 기록의 무료 수정·삭제도 후속 의도로 보존하며, 내 변경/서버 변경 선택을 따른다.
- 로그아웃·계정 전환으로 다른 계정의 플랜 상태를 바꾸지 않도록 플랜 갱신은 계정별 정책만 저장하고 세션이 같은지 재확인한다.

## SQLite 업데이트

DB 버전은 3에서 4로 올라간다. 기존 DB를 열 때 `local_record_changes` 테이블을 자동 추가하며 기존 기록·사진·Outbox를 유지한다. 앱 삭제나 DB 초기화는 필요하지 않다. 레거시 이메일 소유권을 Firebase UID로 옮길 때 이 이력도 함께 이동하고, 계정 탈퇴 때 해당 계정 이력을 정리한다.

변경 이력 도입 전에 이미 삭제하여 아무 이력도 남아 있지 않은 기록은 삭제 의도를 복원할 수 없다. 이 정책은 업데이트 후 기록한 변경부터 적용된다.

## 실제 기기 확인

Firebase 플랜 변경은 [서버 플랜 entitlement 설정](server_plan_entitlement.md)의 테스트 방법을 사용한다. 플랜을 바꾼 뒤 **서버 플랜 새로고침**을 눌러 앱에도 적용되었는지 확인한다.

1. **미전송 기록 수정 후 재승급**: 유료 계정에서 오프라인으로 기록을 저장한다. 서버 플랜을 무료로 바꾸고 연결을 복구해 무료 전환을 확인한 뒤 그 기록을 수정한다. 앱을 완전히 종료한 상태에서 서버 플랜을 유료로 바꾸고 다시 실행한다. 최신 수정이 유지되고, 동기화 후 Firestore와 다른 유료 기기에도 최신 값이 표시되어야 한다.
2. **무료 기간 삭제**: 유료 상태에서 서버에 반영된 기록을 준비한다. 무료로 전환한 뒤 해당 기록을 삭제하고 앱을 재실행한다. 무료 상태에서는 기기에만 삭제가 반영되며 서버 기록은 유지되어야 한다. 다시 유료로 전환하고 동기화하면 서버도 삭제 상태가 되고, 다른 기기에서도 기록이 사라져야 한다.
3. **재실행·새로고침 반복**: 마이그레이션 대기 중 앱 재실행과 플랜 새로고침을 반복한다. Outbox에 같은 최신 변경이 반복 추가되거나 캘린더에 기록이 중복되지 않아야 한다.
4. **계정 전환**: A 계정에 마이그레이션할 기록을 여러 개 준비하고 재승급 직후 로그아웃하여 B 계정으로 접속한다. B의 기록·Outbox에 A의 내용이 없어야 한다. A로 돌아오면 본인 기록의 이전을 재개할 수 있어야 한다.
5. **삭제와 다른 기기 수정의 충돌**: A 기기에서 무료 기간에 기록을 삭제하고 앱을 종료한다. 서버를 유료로 전환한 뒤 B 기기에서 플랜을 새로고침하고 같은 기록을 수정·동기화한다. A 기기를 다시 실행하여 충돌이 표시되면 내 변경을 선택했을 때 삭제, 서버 변경을 선택했을 때 최신 서버 기록 유지가 적용되어야 한다.

응답 유실 및 계정 변경이 정확히 DB await 사이에 발생하는 조건은 자동 테스트로 검증한다. 사진은 기존 정책대로 기기에만 저장한다.

## 자동 검증

`test/plan_migration_integrity_test.dart`에서 재시작 복원, 응답 유실 뒤 영수증 복구, 이전 앱에서 변형된 요청의 충돌 전환, 무료 삭제, 마이그레이션 상태 없이 남은 변경 이력, 기존 충돌 해결, 동시 재개, A→B/A→B→A 세션 변경, 탈퇴 정리, UID 소유권 이전과 충돌 방어를 검증한다. `test/local_database_test.dart`에는 DB v3→v4 업데이트 검증을 추가했다.

```powershell
flutter test --no-pub --concurrency=1
flutter analyze --no-pub
```

2026-10-20 검증: 전체 테스트 180개 통과, 정적 분석 문제 없음. 새 회귀 테스트 14개와 DB 업데이트 테스트 1개를 포함한다. 실제 기기·운영 Firebase에서의 위 수동 절차는 별도로 확인해야 한다.
