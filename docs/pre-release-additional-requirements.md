# 수정사항.txt 추가 요구사항 정리

기준 자료: 사용자가 제공한 `수정사항.txt` 및 감사 기준 HEAD `7929bf8`의 관련 화면.

사용자가 추가한 화면 개선·기능 요구사항을 기록한다. 기존 감사의 결함 목록과 함께 우선순위를 정하되, 이 문서 작성으로 구현을 시작하거나 새 브랜치를 만들지는 않았다.

후속 진행: `refactor/map-record-ui`에서 U-01~U-05를 구현했다. [화면 변경·보존 조건·확인 절차](map_record_ui.md)를 참고한다. U-08/U-09는 `feature/calendar-month-navigation`에서 구현했으며 [연·월 선택과 스와이프](calendar_month_navigation.md)에 검증 범위를 정리했다. U-06은 `feature/top-card-notifications`에서 구현했으며 [상단 카드 알림](top_card_notifications.md)에 동작·검증 범위·수동 확인 절차를 정리했다. U-07은 `feature/calendar-today-summary`에서 오늘의 출조 기록 요약으로 구현했다. [표시 기준과 확인 절차](calendar_today_summary.md)를 참고한다. U-10은 아직 구현하지 않았으며 세부 범위를 확정해야 한다.

## 권장 작업 묶음

1. 기존 감사 High 2건(A-01 인증 경합, A-02 첫 동기화 충돌 재시도)을 먼저 수정한다. 이후 서버 스키마·시작 복구·테스트 실패 등 감사 항목을 처리한다.
2. 지도·기록 화면 정리: U-01~U-05. 예시 브랜치 `refactor/map-record-ui`. 화면 정보 정리와 내부 좌표 보존을 같이 검증한다.
3. 캘린더 이동: U-08/U-09. 예시 브랜치 `feature/calendar-month-navigation`.
4. 공통 상태 알림: U-06. `feature/top-card-notifications`에서 구현 완료. 여러 화면을 건드리므로 독립된 변경으로 검토하고 실제 기기 확인을 진행한다.
5. 오늘의 요약: U-07. `feature/calendar-today-summary`에서 캘린더 버튼과 당일 전체 기록의 요약 상세로 구현 완료. 날짜 겹침·자정 갱신·기록 변경 반영과 실제 기기 확인을 진행한다.
6. 프로필 수정: U-10. 예시 브랜치 `feature/profile-settings`. 인증 경합 수정 후 진행하고 닉네임 변경의 서버 데이터 계약을 함께 다룬다.

위 권장 순서는 최초 계획이다. 코드 감사의 후속 수정은 각 감사 항목의 기록을 참고한다. 추가 요구사항은 U-01~U-09의 구현을 반영했으며 U-10은 후속 범위로 남아 있다. U-06/U-07의 실제 기기 확인·최종 빌드·배포는 실행하지 않았다.
