# 위치 좌표 저장

출조 기록에 선택적 WGS84 위도·경도를 추가한다. 기존 장소 이름은 계속 필수이며, 좌표를 모르는 경우에는 장소 이름만 입력해 저장할 수 있다. 실제 지도·장소 검색·GPS·주소의 좌표 변환은 다음 지도 연동 작업에서 구현한다. 이번 작업은 좌표를 입력·전달받아 저장하고 동기화하는 기반이다.

## 입력과 기록 모델

- `FishingRecord.latitude`, `longitude`는 선택적 `double`이다.
- 두 값이 모두 없거나, 두 값이 모두 있는 경우를 허용한다. 한쪽만 입력하면 저장하지 않는다.
- 위도는 -90~90, 경도는 -180~180을 포함하며 0과 음수도 허용한다. 문자열·범위 초과·NaN·무한대는 저장하지 않는다.
- JSON에서 두 좌표가 없으면 기존 장소명 기록으로 읽는다. 좌표 없는 기록을 다시 저장할 때 불필요한 null 키를 넣지 않아 기존 Outbox payload를 유지한다.
- 기록 작성·수정의 `위도·경도 (선택)`을 펼쳐 입력한다. `좌표 지우기`는 두 입력을 함께 비우며, 저장하면 기존 좌표를 제거한다.
- 메모 등 다른 항목만 수정하면 기존 좌표가 유지된다. 좌표만 수정해도 저장하지 않은 변경으로 취급한다.
- 향후 지도는 `RecordFormPage.initialLocation`, `initialLatitude`, `initialLongitude`로 선택한 위치를 전달할 수 있다.
- 상세 화면에는 좌표가 있는 경우 두 값을 함께 표시한다. 입력값을 임의로 반올림해서 저장하지 않는다.

## SQLite와 서버 형식

SQLite v6에서 `fishing_records.latitude`, `longitude`를 nullable REAL로 추가한다. 기존 본문을 다시 만들지 않고 컬럼을 추가하며, 기존 기록의 두 좌표는 null이다. 기존 조과·사진·독립 사진 아카이브·Outbox·무료 변경 이력·충돌·버전 및 증분 체크포인트는 유지한다. 새 DB와 업그레이드 DB에 같은 좌표 쌍·범위 제약을 적용한다.

Firestore 경로와 소유권은 기존과 같다.

```text
users/{firebaseUid}/records/{recordId}
```

| 기록 종류 | schemaVersion | 좌표 필드 |
|---|---|---|
| 장소명만 있는 활성 기록 | 1 | 없음, 기존 20개 필드 |
| 좌표가 있는 활성 기록 | 2 | latitude·longitude 숫자 쌍, 총 22개 필드 |
| 삭제 tombstone | 1 | 없음, 기존 삭제 형식 |

좌표를 추가하거나 지우면 서버의 기록 `versionNo`도 기존 수정 정책대로 증가한다. 두 좌표를 제거한 활성 기록은 v1 형식으로 저장한다. 서버 v1 기록을 임의로 일괄 변환하거나 기존 장소명에서 좌표를 추측하지 않는다. 잘못된 스키마·추가 필드·한쪽 좌표·범위 초과는 서버 규칙과 앱 읽기 검증에서 거부한다.

좌표가 있는 변경 지문에는 두 좌표도 포함한다. 같은 Outbox ID에 다른 좌표를 넣어 처리 영수증을 재사용할 수 없다. 기존 무좌표 요청의 지문 형식과 해시는 유지하므로 이전 앱에서 저장된 요청도 기존 재시도 절차를 따른다.

## 동기화·충돌·캐시

좌표는 유료 Outbox와 무료 기간 변경 이력의 payload에 포함한다. 앱 재실행·재승급·서버 값 적용·본문 캐시 재복원에서도 유지한다. 기기 사진을 합쳐 기록을 재구성하는 경로에서도 서버의 위치 좌표를 보존한다.

충돌 해결의 `위치` 항목은 장소명·위도·경도를 한 묶음으로 선택한다. 같은 장소 이름이라도 좌표가 다르면 차이를 표시한다. 상대의 무좌표 위치를 선택하면 내 좌표도 제거하고, 내 위치를 선택하면 내 좌표를 함께 유지한다. 위도와 경도를 다른 출처에서 따로 선택해 섞지 않는다.

## 배포와 기기 호환

이번 앱은 기존 v1 기록과 새 v2 기록을 모두 읽는다. **기존 앱 바이너리는 v2 기록을 읽지 못하므로 좌표가 있는 기록을 사용하기 전에 모든 테스트 기기를 새 빌드로 갱신해야 한다.** 운영 전환에서도 기존 클라이언트 업데이트를 먼저 확인해야 한다.

프로젝트 폴더에서 다음 명령으로 수정된 Firestore 보안 규칙을 먼저 배포한다. 이 브랜치를 위한 추가 복합 인덱스는 없다.

```powershell
& "$env:APPDATA\npm\firebase.cmd" deploy --only 'firestore:rules' --project fishingbuild
```

SQLite는 앱 실행 시 자동 업그레이드한다. 별도 SQL 설치나 수동 데이터 삭제는 필요 없다. 이번 작업에서 운영 규칙 배포와 서버 데이터 변경은 실행하지 않았다.

## 실제 기기 테스트

1. **기존 기록:** 새 앱으로 실행하고 이전 기록·사진·과거 월을 조회한다. 장소 이름만 있는 기록이 유지되고 메모를 수정해도 저장되어야 한다.
2. **좌표 저장:** 새 기록의 선택 항목에 위도 `35.1796`, 경도 `129.0756`을 입력한다. 저장·재실행 후 상세와 수정 화면에 같은 값이 표시되어야 한다. 무료 계정에서도 기기에 저장할 수 있어야 한다.
3. **검증:** 한쪽만 입력하거나 위도 `91`, 경도 `181`, 문자 등 잘못된 값을 넣으면 저장이 차단되어야 한다. 두 값을 모두 비우면 저장할 수 있고 `0, 0`도 허용한다.
4. **보존·제거:** 좌표 있는 기록의 메모만 수정해 저장한다. 좌표가 유지되어야 한다. 다시 편집해 `좌표 지우기` 후 저장하면 상세와 Firestore 문서에서 좌표가 제거되어야 한다.
5. **기기 간 동기화:** 새 빌드 두 기기에 같은 유료 계정으로 로그인한다. A에서 좌표를 저장·변경·제거하면 B에도 같은 위치가 반영되어야 한다. Firestore에서는 좌표가 있으면 기록 schemaVersion 2, 없으면 1이다.
6. **오프라인·무료 이전:** 오프라인에서 좌표를 수정한 뒤 재실행·연결 복구한다. 대기열과 좌표가 유지되어 전송되어야 한다. 무료에서 좌표 기록을 만들고 유료로 바꿔도 두 값이 함께 이전되어야 한다.
7. **충돌:** 같은 장소 이름에 서로 다른 좌표를 A/B에서 입력해 충돌을 만든다. 내 변경·상대 변경·직접 병합의 위치 선택에 따라 장소명과 좌표가 함께 반영되어야 한다.
