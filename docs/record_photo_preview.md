# 기록 사진 미리보기·확대·여러 장 선택

브랜치: `perf/record-photo-preview` · 대상: [최초 감사](pre-release-audit.md)의 A-06.

## 수정 내용

기록 작성·편집의 96×96, 상세의 120×120 미리보기가 고해상도 원본 전체를 디코딩하던 경로를 공통 `RecordPhotoThumbnail`과 `RecordPhotoImage`로 교체했다. 원본 파일·저장 경로·사진 첨부 한도·공유 이미지의 원본 읽기 경로는 바꾸지 않는다.

- 표시 크기와 기기의 DPR로 필요한 물리 픽셀 크기를 계산한다.
- 디코더가 알려주는 원본 크기에서 정사각형 `cover`에 필요한 크기를 산출한다. 가로·세로 비율을 유지하고 작은 원본은 디코딩 단계에서 확대하지 않는다.
- 긴 변을 최대 1,200픽셀로 제한하고 두 축을 최소 1픽셀로 보정한다. 극단적인 가로·세로 사진도 제한 없는 크기로 풀거나 0픽셀을 요청하지 않는다. 긴 파노라마는 메모리 상한 때문에 미리보기 선명도가 낮아질 수 있다.
- 파일·메모리 이미지에 같은 제한을 적용한다. 캐시 키에는 원본·물리 픽셀 크기·디코딩 상한을 함께 포함하여 미리보기와 확대 이미지를 구분한다.
- 원본 전체를 먼저 디코딩해 크기를 알아내거나, 축소 파일을 새로 만들어 저장하지 않는다.

일반 `ResizeImage`의 두 축 강제 지정은 비율을 바꿀 수 있고, `fit`은 정사각형 `cover`의 짧은 변에 필요한 픽셀이 부족할 수 있다. 따라서 Flutter SDK의 원본 크기 콜백에 제한된 목표 크기를 전달한다.

## 메모리 소스와 오류 처리

웹의 로컬 사진 읽기 Future는 위젯 State에 보관하여 같은 경로의 재빌드·DPR 변경에서 파일을 반복해서 읽지 않는다. 경로나 reader가 바뀌면 새 Future와 키를 사용하여 이전 이미지가 새 사진의 로딩 중에 남지 않도록 한다. 전역 바이트 Future 캐시는 추가하지 않는다.

빈 경로·읽기 실패·손상된 이미지에는 기존 사진 오류 표시를 제공한다. 파일과 메모리 분기 모두 디코딩 오류를 처리하며, 사진을 불러오지 못했다고 기록이나 사진 파일을 지우지 않는다.

Flutter 이미지 캐시와 웹의 압축된 원본 바이트는 별도 메모리를 사용한다. 이 수정은 주로 디코딩한 픽셀 버퍼를 줄이며 앱 전체 메모리의 같은 비율 감소를 보장하지 않는다.

## 사진 확대 보기

작성·편집·상세 화면의 사진을 누르면 한 장을 전체 화면으로 연다. 두 손가락으로 최대 4배 확대·이동하고, 두 번 탭하면 2.5배 확대와 원래 배율을 전환한다. 상단에서 배율을 초기화하거나 화면을 닫을 수 있다.

확대 화면은 작은 미리보기와 별도로 화면 크기·DPR을 반영해 디코딩하며 긴 변을 최대 3,072픽셀로 제한한다. 동시에 한 장만 표시하고 닫을 때 확대 프레임의 캐시를 해제한다. 저장된 원본 파일은 그대로 사용한다.

확대 중인 사진은 일반 미사용 파일 정리로 삭제되지 않도록 참조를 유지한다. 계정·세션이 바뀌거나 탈퇴 처리로 기록 접근이 잠기면 화면을 닫고 참조를 해제한다. 계정 탈퇴 시 파일을 삭제하는 정책은 유지한다.

## 앨범에서 여러 장 추가

앨범에서 한 번에 여러 장을 골라 선택한 순서대로 첨부할 수 있다. 기존 사진을 포함해 최대 10장, 파일당 10MiB 이하의 JPEG·PNG·WebP라는 기존 제한을 적용한다. 한 장의 공간만 남았을 때와 카메라 촬영에는 단일 선택을 사용한다.

파일 크기 확인·원본 읽기·앱 저장소 복사를 한 장씩 처리한다. 운영체제가 선택 한도를 적용하지 않아도 앱에서는 10장을 넘기지 않는다. 지원하지 않는 파일이나 읽기·복사 실패가 섞이면 정상 사진은 유지하고 제외된 수를 안내한다. 선택 취소 후 다시 추가할 수 있고, 작성을 취소하면 앱이 만든 사본만 정리한다.

## 디코딩 검증

2026-11-16 실제 Flutter 디코더에 생성한 PNG를 전달하여 가로·세로·작은 원본·극단적 비율과 DPR에 따른 결과를 확인했다. 전체 크기의 테스트 이미지는 PNG 인코딩 후 해제하고, 이후 미리보기 프레임을 보관했다.

| 조건 | 원본 해상도 픽셀 버퍼 환산 | 실제 미리보기 픽셀 버퍼 |
| --- | --- | --- |
| 4000×3000 한 장, 상세 120px·DPR 3 | 48,000,000바이트 | 480×360, 691,200바이트 |
| 4000×3000 열 장, 작성·상세 및 여러 DPR 조합 | 480,000,000바이트(약 458MiB) | 합계 6,927,360바이트(약 6.6MiB) |

열 장 테스트의 픽셀 버퍼 합계는 원본 해상도 환산 대비 약 98.56% 작았다. 이는 해당 테스트 조합의 RGBA 버퍼 기준이며, 실제 기기 프로세스의 최대 메모리·GPU 사용량·프레임 시간을 측정한 값은 아니다. 인코딩된 원본 바이트와 파일 내용이 유지되는 것도 확인했다.

- `test/record_photo_image_test.dart`: 실제 디코딩 크기·비율·확대 방지·픽셀 버퍼·원본 보존.
- `test/record_photo_thumbnail_test.dart`: DPR·재빌드·경로 교체·비동기 완료·오류 표시.
- `test/record_photo_viewer_test.dart`: 두 번 탭·두 손가락 확대·초기화·닫기, 원본 보존, 오류·계정 변경·탈퇴 상태와 파일 참조 해제.
- `test/record_photo_ui_test.dart`: 작성·상세 화면의 공통 미리보기와 확대 화면 연결.

- 기존 사진 정리·선택 취소·기록어·공유 관련 테스트로 파일 보존과 기존 동작 확인.

## 실제 기기 확인

1. 기록 작성 → 사진 추가 → 앨범에서 여러 장을 선택한다. 고해상도 가로·세로 사진의 순서와 개수, 입력값 변경 후 유지 여부를 확인한다. 이미 9장이 있을 때는 한 장만 추가할 수 있어야 한다.
2. 작성·편집과 저장된 상세 화면에서 사진을 눌러 두 손가락 확대·이동, 두 번 탭 확대/복원, 초기화·닫기를 확인한다. 돌아온 뒤 입력값과 사진 목록이 유지되어야 한다.
3. 앨범 선택을 취소한 뒤 다시 선택하거나 카메라로 촬영한다. 미지원 형식·10MiB 초과 파일이 선택되는 환경에서는 제외 안내와 정상 사진 보존을 확인한다.
4. 저장 후 상세·편집을 반복해서 연다. 사진 제거 후 저장·작성 취소 시 남은 사진과 순서가 정상이고, 원래 갤러리 파일은 유지되는지 확인한다.
5. 해당 조과의 기록어 공유 이미지를 확인한다. 미리보기 축소가 공유용 원본에 적용되지 않고 사진이 정상 표시되어야 한다.

저장된 사진이 없는 다른 기기의 기존 표시와 누락 파일의 오류 안내는 그대로 사용한다. DB 설정·마이그레이션·Firebase 규칙 배포는 필요하지 않다.
