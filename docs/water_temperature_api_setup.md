# 관측 수온 API 연동

지도에서 바다·해안으로 판별된 위치에 가까운 국립해양조사원 관측소의 최신 수온을 표시한다. 날씨와 조석은 별도로 조회하며 한 서비스의 오류가 다른 서비스의 값을 지우지 않는다. 수온은 예보가 아닌 관측값이다. 조석 날짜를 과거·미래로 바꾸어도 수온을 그 날짜의 예측값으로 바꾸지 않으며, 수온 아래 관측소명과 실제 관측 시각을 표시한다.

## 신청과 실행

1. 공공데이터포털의 [해양수산부 국립해양조사원_조위관측소 실측 수온 조회](https://www.data.go.kr/data/15142506/openapi.do)에 활용 신청한다. `연속정보 수온(3분)`과 구분하며 서비스 URL은 `https://apis.data.go.kr/1192136/surveyWaterTemp`다. 조석 API의 승인과 별도이므로 이 서비스도 승인 상태인지 확인한다.
2. 같은 공공데이터포털 인증키를 사용하면 기존 `tide.local.json`의 `KHOA_SERVICE_KEY`를 그대로 사용한다. 새 설정 파일을 만들 필요가 없다.
3. 수온용으로 다른 키를 사용할 때만 `tide.local.json`에 `KHOA_WATER_TEMPERATURE_SERVICE_KEY`를 추가한다. 이 항목을 빈 문자열로 추가하면 공통 키 대신 빈 키가 적용되므로, 사용하지 않을 때는 항목을 생략한다.

기본 설정:

```json
{
  "KHOA_SERVICE_KEY": "공공데이터포털 인증키"
}
```

`tide.local.json`은 Git에서 제외된다. 키와 인증키가 담긴 요청 주소는 로그·문서·오류 화면에 출력하지 않는다. 인코딩 키는 한 번만 디코딩하고 `+`는 보존한다.

프로젝트 최상위에서 기존 실행을 종료하고 실행한다.

```powershell
& "C:\flutter\bin\flutter.bat" run --dart-define=FIREBASE_AUTH_ENABLED=true --dart-define-from-file=kakao.local.json --dart-define-from-file=weather.local.json --dart-define-from-file=tide.local.json
```

## 조회 기준

- 공식 주소: `https://apis.data.go.kr/1192136/surveyWaterTemp/GetSurveyWaterTempApiService`
- 요청: `serviceKey`, `obsCode`, KST 날짜 `reqDate=YYYYMMDD`, `min=10`, `type=json`, `pageNo`, `numOfRows=300`. 기본적으로 오늘 날짜를 조회하며 최근 2시간 범위가 자정을 넘으면 전날도 확인한다. `min`은 출력되는 관측 시간 간격이다.
- [공식 조위관측소 목록](https://www.data.go.kr/data/15146602/fileData.do)의 2025-08-18 자료에서 과거 지점과 해양과학기지를 제외한 DT 지점 52개를 사용한다. 조석 예보용 84개 지점과 수온 관측소 목록은 구분한다. 목록에 있는 지점도 센서가 중단되거나 수온을 제공하지 않을 수 있다.
- 선택 위치에서 직선거리 50km 이내의 가까운 관측소를 조회한다. 자료 없음·관측소 또는 항목 중단일 때만 최대 세 지점까지 확인한다. 인증·통신·잘못된 응답 오류에는 다른 지점을 연속 조회하지 않는다.
- 응답 `response.header/body.items.item`에서 `wtem`, `obsrvnDt`, `obsvtrNm`, `lat`, `lot`를 읽는다. 관측소 이름·좌표·요청 날짜가 일치하는지 검사한다. 날짜와 시각이 없는 문자열은 KST로 해석해 UTC로 보관하며 기기 시간대와 무관하게 화면에서는 KST로 표시한다.
- 공식 문서는 관측 시각 형식과 실시간 자료임을 안내하며, 모든 센서의 지연 상한을 보장하지 않는다. **관측 후 2시간 이내**는 앱의 최신값 표시 기준이다. 미래 관측 시각, 결측값, 유한하지 않은 숫자 및 -5~45℃ 밖의 값은 표시하지 않고, 실제 0℃는 보존한다.
- 최근 2시간 범위가 KST 자정을 넘으면 오늘과 전날 자료를 함께 조회해 가장 최근의 유효 관측값을 사용한다. 한 날짜의 자료 없음·시간 초과·비정상 응답이 있어도 다른 날짜에 유효한 실제 관측값이 있으면 시각을 그대로 표시한다. 두 날짜 모두 유효한 값이 없을 때만 자료 없음이나 통신 오류를 반환한다. 02:00 이후에는 전날의 값이 유효 범위 밖이므로 추가 조회하지 않는다.
- 관측소·요청 날짜별 성공과 자료 없음 결과를 10분 캐시한다. 같은 요청은 공유하고 캐시는 최대 64개다. 다른 장소에서 같은 관측소를 조회해도 결과는 각 선택 장소에 따로 연결한다.
- 자정 전후의 두 날짜도 위 캐시·동시 요청 공유를 사용한다. 유효 자료가 없는 경우 다른 관측소 조회는 계속 자료 없음에만 허용하며, 통신·인증 오류를 이유로 지점 재시도를 늘리지 않는다.
- 요청별 12초 제한, 응답 512KiB 제한, 최대 5페이지를 적용한다. 부분 페이지를 정상 자료로 처리하지 않고 인증키가 포함될 수 있는 원문 오류를 외부로 넘기지 않는다.
- 민물·내륙·판별 불가 위치에서는 수온 API를 호출하지 않는다. 위치 변경, 민물 전환, 탭 종료 또는 오프라인 전환 뒤 도착하는 이전 응답은 무시한다. 연결 복구 시 다시 조회한다.
- 없거나 조회에 실패한 값은 `제공되지 않음`으로 표시한다. 재시도 버튼은 수온만 다시 조회하며 날씨·조석 요청을 반복하지 않는다. 기온이나 이전 장소의 수온으로 빈 값을 채우지 않는다.

## 기록 자동 입력

지도와 상세 화면에서 기록 작성으로 이동할 때 관측 정보를 전달한다. 새 기록의 장소명·위경도가 같고, 오늘의 기록 시작이 관측 이후 1시간 이내이며 현재 시각보다 1분 이상 미래가 아닐 때 자동 입력한다. 1분은 화면 이동 중 시각 차이를 허용하기 위한 앱의 기준이다.

[과거 수온 조회](historical_external_data.md)는 같은 API의 다른 날짜 자료를 별도 과거 모델로 선택한다. 현재 수온의 최신값 조건과 오늘 기록 제한은 그대로 유지한다.

날짜·시작 시간·장소·좌표를 바꾸어 조건에서 벗어나면 자동 입력값만 지운다. 사용자가 직접 바꾸거나 비운 값, 명시적으로 전달한 초기 수온, 기존 기록의 수온은 보존한다. 민물에서 여는 기록에는 자동 관측값을 전달하지 않는다. 실제 저장값은 기존 수온 필드를 사용하므로 SQLite·Firestore 스키마와 보안 규칙 변경은 없다.

## 실제 기기 확인

1. 수온 서비스 활용 승인 후 위 명령으로 재실행한다. 흰여울문화마을·부산항 같은 해안 지점을 선택하고 실제 수온, 관측소와 시각을 확인한다.
2. 같은 위치의 지도 상세에서도 같은 수온을 확인한다. 날씨 조회가 실패해도 수온은 별도로 표시되어야 한다.
3. 기록 작성에서 오늘의 수온이 자동 입력되는지 확인한다. 시작 날짜를 어제나 내일로 바꾸면 자동 수온은 지워져야 한다.
4. 수온을 직접 바꾸거나 비운 뒤 날짜·장소를 바꾸어도 해당 입력을 덮어쓰지 않아야 한다. 저장된 기록을 다시 열어 수정할 때도 기존 수온을 보존한다.
5. 한강·시화호·서울시청으로 바꾸면 수온과 재시도 버튼이 사라져야 한다. 바다 조회 중 바로 민물로 바꾸어도 늦게 도착한 수온이 나타나면 안 된다.
6. 오프라인·자료 없음·서비스 오류에서는 `제공되지 않음`을 표시하고, 수온 재시도는 날씨·조석을 재조회하지 않아야 한다.
7. 조석 날짜를 미래로 바꾸어도 수온은 실제 관측 시각을 유지한다. 미래 수온 예보처럼 표시되면 안 된다. 작은 화면과 큰 글씨에서 값·관측 안내가 잘리지 않아야 한다.
8. 자정 직후 현재 수온을 조회할 때 새 날짜 자료가 아직 없어도 전날의 최근 2시간 이내 실제 관측값은 표시되어야 한다. 관측 날짜·시각을 오늘로 바꾸어 표시하면 안 된다.

## 현재 외부 연결 확인

2026-11-03 최초 확인에서는 기존 `tide.local.json`의 동일 인증키로 조석 API는 정상(`00/NORMAL_SERVICE`), 수온 API는 HTTP 403을 반환했다. 사용자가 수온 서비스를 신청한 후 같은 인증키로 다시 조회해 실제 성공 응답을 확인했다. 흰여울문화마을 대표 좌표에서 부산 관측소의 18.9℃(2026-11-03 12:50 KST 관측)를 받았으며, 조회 시각 13:01 KST 기준 최신값 조건을 통과했다. 이 값은 검증 시점의 관측값이며 고정값이 아니다. 새 인증키나 추가 설정은 사용하지 않았다. 기기 화면은 사용자가 확인한다.
