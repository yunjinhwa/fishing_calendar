# 과거 날씨·수온 조회

지도 상세의 `과거 정보 조회`에서 선택한 장소의 날짜와 KST 시각을 지정한다. 기상청의 과거 관측 날씨·기온과 바다의 국립해양조사원 관측 수온을 별도로 조회하고, 같은 시점의 출조 기록 작성을 시작할 수 있다. 오늘의 예보나 현재 수온을 과거 자료 대신 사용하지 않는다.

## API 활용 신청

기존 `weather.local.json`의 기상청 API허브 키와 `tide.local.json`의 공공데이터포털 키를 사용한다. 기상청의 초단기예보 활용 승인과 아래 관측 API의 승인은 별도다.

1. [기상청 API허브 시간자료 화면](https://apihub.kma.go.kr/apiList.do?apiSeq=2)에 로그인한다. `종관기상관측(ASOS)`의 `1. 지상 관측자료 조회 → 1.1 시간자료` 오른쪽 `API 활용신청`을 누른다. 주소에 `kma_sfctm2.php`가 있는 항목이다.
2. [기상청 API허브 지점정보 화면](https://apihub.kma.go.kr/apiList.do?seqApi=2&seqApiSub=317)에서 `1. 지상관측 지점정보 조회 → 1.1.1 지상` 오른쪽 `API 활용신청`을 누른다. 주소가 `stn_inf.php?inf=SFC`인 항목이다. 과거 시점의 관측소 위치를 확인하기 위해 사용한다.
3. 수온은 기존에 승인된 [조위관측소 실측 수온 조회](https://www.data.go.kr/data/15142506/openapi.do)를 그대로 사용하므로 별도의 과거 수온용 인증키가 필요하지 않다.

활용 목적은 `낚시 캘린더 앱의 위치별 과거 날씨 조회`로 작성할 수 있다. 두 기상청 항목이 모두 승인되면 기존 API허브 키로 조회한다. 별도 API허브 키를 사용할 때만 `weather.local.json`에 `KMA_HISTORY_SERVICE_KEY`를 추가하고, 별도 제공처 설정이 필요할 때만 `KMA_HISTORY_API_PROVIDER: apihub`를 추가한다. 기본 제공처는 `KMA_HISTORY_API_PROVIDER → KMA_API_PROVIDER → apihub` 순으로 결정하며 과거 날씨는 API허브만 지원한다. 공공데이터포털 예보 키를 API허브로 자동 전송하지 않는다. 키를 사용하지 않는 항목에 빈 문자열로 추가하지 않는다.

로컬 설정 파일은 Git에서 제외된다. 기존 실행을 종료하고 프로젝트 최상위에서 실행한다.

```powershell
& "C:\flutter\bin\flutter.bat" run --dart-define=FIREBASE_AUTH_ENABLED=true --dart-define-from-file=kakao.local.json --dart-define-from-file=weather.local.json --dart-define-from-file=tide.local.json
```

## 날짜·시각과 표시

- 앱의 조회 선택 범위는 2020-01-01부터 현재 시각 이전의 완료된 시간까지다. 날짜를 오늘로 바꾸면 아직 끝나지 않은 시간은 선택할 수 없으며, 한국 시각 자정에는 전날 23시가 마지막 선택값이다. 이 범위는 앱 정책이며 모든 날짜에 센서 자료가 존재한다는 뜻은 아니다.
- 최초 선택은 전날의 같은 시간이다. KST 날짜·시간을 UTC로 변환해 요청·비교하며, 화면에는 KST로 표시한다.
- 과거 날씨와 수온은 독립적으로 로딩·재시도한다. 한쪽이 없거나 실패해도 다른 쪽 결과와 기록 작성 기능을 유지한다. 없는 값은 `제공되지 않음`으로 표시한다.
- 물때는 바다·해안에서 선택한 날짜와 주변 조석 지점 기준으로 계산한다. 과거 만조·간조 조회는 기존 지도 조석 날짜 선택 기능을 이용한다.
- 민물·내륙·판별되지 않은 위치에서는 수온을 조회하거나 표시하지 않는다. 장소명만 있고 좌표가 없는 경우 API를 호출하지 않고 지도에서 위치를 선택하도록 안내한다.
- 날짜·시간·장소·수역 변경, 화면 종료 또는 오프라인 전환 뒤 도착한 이전 응답은 현재 선택을 덮어쓰지 않는다. 네트워크 복구 시 현재 선택을 다시 조회한다.

## 과거 날씨

- 기상청 API허브의 `kma_sfctm2.php`에 `tm=YYYYMMDDHHmm`, `stn=0`, `help=1`, `authKey`를 보낸다. 해당 시각의 모든 종관기상관측 지점 자료를 한 번에 받는다.
- `stn_inf.php`에 `inf=SFC`, `stn=0`, 동일한 `tm`, `help=1`, `authKey`를 보내 당시 존재한 지점의 좌표를 받는다. 현재 관측소 좌표를 과거 위치라고 가정하지 않는다.
- 실제 자료가 있는 지점 중 선택 위치에서 50km 이내의 가까운 지점을 사용한다. `TA`는 관측 기온, `WW/WC`는 현상 코드, `CA_TOT`는 관측 전운량이다. 공식 국내·WMO 코드와 운량으로 날씨를 표시하며, 결측이나 무강수만으로 맑음이라고 추정하지 않는다. 실제 -9℃는 유효한 기온으로 유지한다.
- 응답 도움말과 고정 형식을 검증한다. 한글 지점명이 손상된 예전 인코딩 응답은 잘못된 이름 대신 관측소 번호를 표시하며 숫자 자료를 보존한다. 원문 인증·통신 오류와 키가 포함된 요청 URL은 사용자 화면이나 로그로 넘기지 않는다.
- 시각별 성공 스냅샷은 24시간, 자료 없음은 10분 캐시한다. 최대 128개를 보관하고 동시 요청을 공유한다. 지점을 공유해도 결과의 선택 장소·좌표는 각 요청에 따로 연결한다.
- 요청별 12초, 응답별 512KiB 제한을 적용한다. 인증 실패에 다른 제공처나 예보 API를 대신 호출하지 않는다.

## 과거 수온

- 현재 수온과 같은 `surveyWaterTemp/GetSurveyWaterTempApiService`에 선택한 KST 날짜 `reqDate`, `min=10`과 관측소 코드를 보낸다. 수온 전송·페이지 처리·지점 검증은 현재 조회와 공유한다.
- 선택 시각보다 늦지 않은 같은 KST 날짜의 표본 중 1시간 미만 차이가 나는 가장 최근 값을 사용한다. 이후 시각의 값, 날짜가 다른 값, 결측·비정상 값으로 대체하거나 보간하지 않는다.
- 52개 연안 관측소 중 50km 이내 가까운 순으로 최대 세 지점을 확인한다. 다른 지점으로의 재시도는 자료 없음에만 허용한다.
- 과거 날짜의 원본 표본은 관측소·날짜별로 24시간 캐시한다. 오늘 자료와 자료 없음 결과는 10분, 통신·인증 오류는 반복 요청을 줄이기 위해 30초 동안 보관한다. 최대 128개이고 진행 중 요청을 공유한다.
- 현재 수온의 `관측 후 2시간 이내` 제한은 유지한다. 과거 조회는 이 제한을 완화한 현재 값이 아니라 별도 과거 관측 모델로 처리한다.

## 기록 작성

`이 정보로 기록 작성`을 누르면 회원 접근 제한을 확인한 뒤 선택한 과거 시각을 출조 시작으로, 기본 종료를 2시간 뒤로 설정한다. 조회한 날씨·기온·수온은 장소명·좌표·대상 시간이 맞는 새 기록에만 자동 입력한다. 시각의 저장 기준은 UTC로 일관되게 유지하고 기존 기록 화면은 기기의 현지 시각으로 표시한다.

날짜·시간·장소·좌표를 바꿔 적용 조건을 벗어나면 자동 입력값만 비운다. 입력을 직접 수정하거나 비운 경우, 명시적인 초기값, 기존 기록 수정값은 보존한다. 조건을 다시 맞추면 사용자가 건드리지 않은 과거 값만 다시 적용할 수 있다. 관측 표본보다 1시간 이상 늦은 출조 시작에 과거 수온을 재사용하지 않는다. 기존 필수값·저장·접근 검증은 유지하며 SQLite·Firestore 스키마와 보안 규칙은 변경하지 않는다.

## 기기 테스트

1. 흰여울문화마을 같은 해안 위치의 지도 상세에서 `과거 정보 조회`를 연다. 같은 장소와 좌표가 전달되고 전날 날짜·시간이 선택되는지 확인한다.
2. 날짜와 시간을 바꾸어 해당 시각의 관측 결과·관측소·시각이 표시되는지 확인한다. 오늘의 기온이나 현재 수온이 대신 나오면 안 된다.
3. 한쪽 조회에 실패해도 다른 결과가 남는지, `날씨 다시 조회`와 `수온 다시 조회`가 해당 항목만 갱신하는지 확인한다.
4. 날짜·시간을 빠르게 여러 번 바꿔 이전 응답이 마지막 선택을 덮어쓰지 않는지 확인한다.
5. 민물·내륙과 좌표 없는 위치에서는 수온이나 불필요한 API 조회가 없는지 확인한다.
6. 조회 결과로 기록 작성을 열어 시작 날짜·시간과 자동 입력값을 확인한다. 시작 시간·장소 변경 시 자동 값은 지워지고 직접 수정하거나 비운 값은 보존되어야 한다. 기존 기록 수정과 현재 날씨·수온 입력도 유지되어야 한다.
7. 오프라인에서는 결과가 없는 새 조회를 제공되지 않음으로 표시하고 연결 복구 후 다시 조회한다. 비회원의 기록 작성은 로그인 안내로 이동해야 한다.
8. 글자 크기를 키운 작은 화면에서도 시간 선택·수온과 관측 안내·기록 작성 버튼이 잘리지 않는지 확인한다.

## 실제 연결 상태

2026-11-03 최초 확인: 흰여울문화마을 대표 좌표에서 2026-11-02 12:00 KST의 부산 관측소 수온 19.2℃를 실제 서비스로 조회했다. 같은 실행에서 현재 수온 18.9℃(2026-11-03 13:10 KST 관측)도 정상 조회해 과거와 현재를 구분했다. 당시 기상청의 과거 시간자료·지점정보는 기존 키에 HTTP 403을 반환해 활용 신청을 안내했다.

이후 같은 설정으로 재조회해 두 기상청 API 모두 HTTP 200을 확인했다. 실제 응답의 지점 식별자 헤더가 `STN_ID` 대신 `STN`으로 표시되고 뒤쪽에 같은 이름의 코드 열이 다시 나오는 형식을 지원하도록 수정하고 회귀 테스트를 추가했다. 실제 서비스로 같은 과거 시각의 부산 기상관측소 159번에서 `맑음`, 기온 17.1℃와 부산 수온 19.2℃를 수신했다. 동일 실행의 현재 수온은 19.0℃(2026-11-03 23:30 KST 관측)로 과거 값과 분리했다. 이 값은 검증 시점의 실측값이며 고정값이 아니다. 새 키나 추가 설정 파일은 사용하지 않았다. 실제 기기 화면은 사용자가 위 절차로 확인한다.
